1.1 为什么要做

客户需要在自有小程序中向用户展示推广活动，并按渠道维度排除特定用户群体，同时根据用户是否携带 A 参数自动选择不同的跳转目标。当前缺少统一的客户自助投放入口，客户无法自主创建活动、配置排除渠道和双层跳转。

        ↓
投放效率低，无法支持客户灵活调整

        ↓

        ↓

        ↓

        ↓
用户点击跳转：有 A 参 → A 参跳转；无 A 参 → 默认跳转

客户创建活动投放时，从已存在的联盟活动和第三方活动中选择跳转目标。联盟活动筛选条件为：同时具备小程序路径和 H5 模板的已上架联盟活动。第三方活动为 B04 中已发布的第三方活动。

1.3 最终目标

  • 客户自主投放： 客户在商户后台独立完成活动投放的创建、配置（含排除渠道和双层跳转）和上下架管理，无需依赖总后台运营介入。
  • C 端精准可见与跳转： 用户进入今日活动页面后，先通过 B 参数排除过滤，再按整点分组查看活动卡片；点击后根据 A 参数自动选择跳转目标（有 A 参优先，无 A 参默认兜底）。
  • 渠道定向排除： 客户选择要排除的渠道，活动对命中排除列表的用户不可见，未命中排除列表的用户正常可见。

2.1 多方业务泳道图

本功能仅涉及两个参与方：客户（通过商户后台操作）和 C 端用户（在小程序中查看和点击活动）。无总后台参与。

2.2 阶段划分与阅读说明

后续正文按业务实际发生顺序线性展开，不按操作端分别集中介绍。根据当前业务闭环，划分为两个阶段：

1. 第一阶段：客户配置活动投放（主要参与方：客户端后台）：客户在商户后台查看活动投放列表，创建新的活动投放、配置基本信息、排除渠道和双层跳转（A 参 / 默认）、管理上下架。本阶段的结果决定 C 端用户能看到哪些活动以及点击后跳转至何处。

2. 第二阶段：C 端活动展示与跳转（主要参与方：C端用户）：用户进入今日活动页面，系统先通过 B 参数执行排除过滤，再按整点分组展示命中活动；用户点击后，系统根据 A 参数选择跳转目标。

两条跳转类型路径（联盟/第三方）完成目标选择后，统一在跳转链接生成环节携带参数输出最终 URL。

03 产品与技术补充规则
  • **B 参数排除过滤（可见性控制）**：页面加载时拉取当日所有已上架活动投放。对每条活动，系统读取当前用户 B 参数（渠道标识），与活动的"投放用户（排除）"列表比对。若 B 参数命中排除列表中的任一渠道，该活动对此用户隐藏；若未命中（包括用户无 B 参数或排除列表为空），该活动对此用户可见。过滤在数据层完成，不影响分组和排序逻辑。
  • **A 参数跳转判定（跳转目标选择）**：用户点击活动卡片时，系统读取当前用户 A 参数。若用户有 A 参数且该活动已配置 A 参跳转（A-跳转方式非空），则使用 A 参跳转配置生成跳转链接。否则（用户无 A 参数，或活动未配置 A 参跳转），使用默认跳转配置生成跳转链接。
  • **状态实时计算（北京时间）**：C 端页面每次进入时以当前北京时间与活动投放的每天开始时间比较，实时计算每个活动的状态标签。不依赖定时刷新或后端状态字段。
  • **排序规则**：同分组内活动卡片按状态优先级排序：进行中 → 即将开始 → 未开始 → 已结束。同状态内按活动创建时间升序。
  • **分组规则**：仅展示当天（北京时间日期）的活动投放。已过期的整点时间（当前时刻 > 开始时间+60分钟）仍展示对应分组，但该组下卡片均标记为"已结束"。
  • **跳转参数透传**：点击跳转时，系统在目标 URL 后拼接用户标识、A 参数（如有）、B 参数和当前活动投放 ID，供下游归因使用。
  • **页面加载策略**：页面进入时拉取当日所有已上架活动投放，客户端执行 B 参数排除过滤，再根据北京时间实时计算状态和排序。不依赖服务端状态字段，避免时区不一致导致的展示偏差。

6.1 跨阶段业务规则

  • 上架即时生效：客户在商户后台上架活动投放后，C 端今日活动页面即时可见该活动（下次进入页面或下拉刷新时，同时经 B 参数排除过滤）。
  • 编辑即时生效：客户编辑活动投放的任何字段并保存后，C 端即时反映修改内容。
  • 下架即时移除：客户下架活动投放后，C 端即时不可见该活动。
  • B 参数排除优先：C 端可见性判断优先执行 B 参数排除过滤，命中排除列表的活动无论其他配置如何均不可见。
  • A 参数优先于默认：跳转目标选择优先使用 A 参跳转配置（需用户有 A 参数且活动已配置），否则兜底使用默认跳转配置。

6.2 业务分支与汇合规则

  • 联盟路径：客户选择跳转方式=联盟 → 选联盟活动（仅筛同时有小程序路径和 H5 模板的） → 选小程序或 H5 → H5 需选模板。
  • 第三方路径：客户选择跳转方式=第三方 → 选第三方活动。
  • A 参分支：A 参跳转配置选填——配置后，有 A 参数用户优先走此分支；未配置时，有 A 参数用户也走默认分支。
  • 汇合点：所有分支在跳转链接生成环节汇合，统一携带归因参数输出最终 URL。

8.1 文档设计理念

本文档采用"人类阅读正文 + AI 维护说明"双层结构。第 1～7 章用于人类阅读，第 8 章用于 AI 维护。

8.2 正文组织原则

  • 正文按业务实际发生顺序展开：客户配置 → C 端展示。
  • 泳道图是流程唯一事实源，所有页面小节的"当前环节"引用泳道图节点。
  • 后台页面按"列表页 → 页面编辑类"顺序：先让读者了解列表全貌，再进入创建编辑。
  • 页面编辑类字段按业务分组（基本信息、投放设置、跳转配置、默认跳转配置）拆为四张 7 列子表，遵循模板分组规则。
  • C 端页面对应移动端展示页结构：页面状态全览 → 字段标注 → 状态差异 → 节点跳转 → 产品技术规则。

8.3 泳道和参与方识别规则

  • 仅两个参与方：客户端后台（客户）和 C 端用户。无总后台。
  • 联盟活动（B02）和第三方活动（B04）是上游已就绪的数据资源，不是本功能的参与方。
  • A 参数和 B 参数是 C 端用户身上携带的标识，由开发侧定义具体字段，本文档不展开。

8.4 上游数据依赖

  • 联盟活动（B02）：本功能从已上架的联盟活动中筛选具有小程序路径且具有 H5 模板的活动，供客户选择。
  • 第三方活动（B04）：本功能从已发布的第三方活动中筛选，供客户选择。
  • H5 模板：关联至联盟活动或第三方活动的 H5 模板数据，供跳转方式=联盟+H5 或跳转方式=第三方时选择。
  • A 参数：C 端用户携带的参数，由开发定义，用于判定跳转时取 A 参配置还是默认配置。
  • B 参数：C 端用户携带的渠道参数，用于与排除列表比对、控制活动可见性。

8.5 术语与字段同步

  • "活动投放"：本功能的核心业务对象，客户创建的一条投放记录。
  • "联盟活动"：B02 中运营维护的联盟推广活动。
  • "第三方活动"：B04 中维护的第三方推广活动。
  • "投放用户（排除）"：客户选择的排除渠道，B 参数命中时活动对用户不可见。
  • "A参跳转配置"：用户有 A 参数时优先使用的跳转配置（选填，未配置时兜底到默认）。
  • "默认跳转配置"：用户无 A 参数时的兜底跳转配置（必填）。
  • "每天开始时间"：活动在 C 端出现的时间（整点 HH:00）。

8.7 不得混淆

  • 活动投放 ≠ 联盟活动 ≠ 第三方活动：活动投放是客户创建的投放记录，联盟活动和第三方活动是上游活动资源。
  • 上架/下架（活动投放状态）≠ 已上架/已下架（联盟活动状态）≠ 已发布/已删除（第三方活动状态）。
  • C 端卡片状态（未开始/即将开始/进行中/已结束）是实时计算值，不是持久化字段。
  • 投放用户（排除）是反向排除逻辑，不是正向包含——勾选的渠道被排除，未勾选的渠道畅通。
  • A 参跳转配置为空 ≠ 活动无法跳转——此时走默认跳转配置。
  • B 参数命中排除列表 → 不可见；B 参数未命中 → 可见。无 B 参数 = 未命中 = 可见。

投放用户（排除）字段可见性： 该字段仅对特定账号可见。非特定账号创建活动投放时不展示该字段，系统默认不排除任何渠道（即所有渠道用户可见）。

上架约束： 上架前不校验跳转目标是否存在或有效——跳转目标可能后续被删除或下架，在跳转时实时判断。但保存时必须校验默认跳转配置完整（默认跳转为必填）。

下架影响： 下架后 C 端即时不可见，不影响已产生的历史点击数据。

编辑即时生效： 编辑保存后 C 端今日活动页面即时更新，无需用户刷新。
🔍业务背景
当前环节：② 创建活动投放 / ⑩ 编辑活动投放

页面路径：商户后台 > 活动管理 > 活动投放 > 创建活动投放（或编辑活动投放）

对下游影响：保存后形成活动投放记录；上架前需在活动链接页面（4.3）配置投放链接，否则 C 端点击时兜底使用默认跳转逻辑；上架后出现在 C 端今日活动页面（经 B 参数排除过滤）

表格类型：页面编辑类
⚙列表交互
创建/编辑为独立页面，不设列表交互。本页面仅有一个"保存"操作，其交互和校验在业务逻辑中说明。
💡业务逻辑
保存校验：

- 必填项：活动主图、活动名称、每天开始时间、默认-跳转方式。
- 跳转配置整体选填（跳转方式为空时，有 A 参数的用户也走默认跳转）。
- 默认跳转配置为必填：默认-跳转方式=联盟时，默认-联盟活动和默认-联盟跳转方式必填；默认-联盟跳转方式=H5 时默认-H5 模板必填。默认-跳转方式=第三方时，默认-第三方活动必填。
- 跳转配置填写时，校验规则同默认跳转：跳转方式=联盟时，联盟活动和联盟跳转方式必填；跳转方式=第三方时，第三方活动必填。

每天开始时间去重与排序： 保存时系统自动对所选整点时间去重并升序排列。已到达的整点时间（以保存时刻北京时间判断）在编辑时保留历史选择但标注"已过期"；新增时不可选已过期的整点。

投放用户（排除）字段可见性： 仅特定账号登录后可见此字段；非特定账号不展示，保存时默认不排除任何渠道。

跳转方式切换联动： 切换跳转方式（联盟↔第三方）时，清空已选的目标活动字段值。切换默认-跳转方式时同理。跳转配置和默认配置各自的联动相互独立，不互相影响。

C 端运行时判定逻辑：

1. 可见性（B 参数排除）：用户进入今日活动页面，系统读取用户 B 参数。若 B 参数命中活动投放的排除渠道列表，则该活动对此用户隐藏；若未命中（包括用户无 B 参数），则该活动对此用户可见。
2. 跳转目标（A 参数判定）：用户点击可见活动卡片，系统读取用户 A 参数。若有 A 参数且活动已配置跳转配置，则使用跳转配置生成跳转链接；若用户无 A 参数或跳转配置未配置，则使用默认跳转配置生成跳转链接。

跳转链接生成： C 端用户点击活动卡片时，系统按上述判定逻辑实时拼接跳转链接。对应的跳转目标（联盟活动或第三方活动）在跳转时被删除或下架，则 Toast 提示"活动暂不可用"并阻止跳转。

编辑即时生效： 活动投放编辑保存后，C 端今日活动页面即时反映修改内容（名称、主图、副标题、时间、排除渠道、跳转目标）。

无额外控制关系时的默认行为： 创建页面加载时，跳转方式和默认-跳转方式均默认为空（默认-跳转方式必填，页面会校验）。两组跳转配置的子字段在对应控制字段未选择时均置灰不可交互；控制字段选择后，对应字段组解锁。

对下游影响：配置完成的活动链接将作为 C 端用户点击活动卡片后的最终跳转目标；未配置链接的活动即使上架也无法跳转，兜底使用 4.2 中的默认跳转逻辑

业务用途：点击右侧活动行的「配置」或「编辑」按钮，弹出「配置活动链接」弹窗。弹窗上半区展示活动详情（同4.1详情字段，全部置灰只读），下半区为链接配置区（投放场景可编辑 + 投放内容子字段按场景联动展示）。配置完成后弹窗关闭，清单刷新，该活动行更新为"已配置"状态并展示对应的投放场景标签。
🪟弹窗结构
上半区 — 活动详情（①② 展示信息，全部置灰只读）：
展示活动主图、活动名称、活动副标题、跳转配置、每天开始时间、投放用户（排除）、状态、创建时间等 4.1 详情字段，全部不可编辑。

下半区 — 链接配置（③④⑤ 可编辑）：
• 投放场景下拉选择（①联盟+小程序 ②联盟+H5 ③第三方+小程序 ④第三方+口令 ⑤第三方+H5）
• 投放内容子字段按场景联动：①②联盟场景子字段全部只读自动带入；③④⑤第三方场景的路径/口令/H5链接可手动填写
• 弹窗底部设「保存」和「取消」按钮
💡业务逻辑
推广位与活动关联： 活动投放创建（4.2）时不绑定推广位。客户进入活动链接页面后，先选择推广位，再为该推广位下的活动逐条配置链接。同一活动可在多个推广位下配置不同的链接参数。

投放场景联动： 选择投放场景后，投放内容的子字段组合自动切换。切换投放场景时，已填写的投放内容清空。

联盟活动数据只读： 投放场景包含"联盟"时，子字段数据从联盟活动（B02）自动带入，不可手动修改。投放场景包含"第三方"时，appid/H5模板从第三方活动（B04）自动带入（只读），其余字段（路径/口令/H5链接）可手动填写。

保存校验： 保存时必须确保投放场景和投放内容子字段均填写完整。未配置投放场景的活动在 C 端点击时使用 4.2 中配置的默认跳转逻辑兜底。

配置状态展示： 右侧活动清单中，已配置链接的活动显示投放场景标签（如"联盟+小程序"、"第三方+H5"），未配置的活动显示"—"或"未配置"标记。
