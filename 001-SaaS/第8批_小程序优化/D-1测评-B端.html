1.1 为什么要做

当前 SaaS 平台缺少面向 C 端用户的内容运营工具。商户需要一种轻量级的图文内容形式，能够通过测评、种草、推荐等场景触达用户，引导用户浏览、互动和分享，从而提升用户停留时长和转化机会。

text
改造前

商户无自主可配置的 C 端内容展示工具，依赖固定模板或外部链接。


改造后

总后台配置发布人
        ↓
总后台创建测评帖子（关联发布人、设置起始互动数据）
        ↓
上架后 C 端用户浏览测评列表 → 点击进入详情 → 点赞 / 收藏 / 转发

1.3 最终目标

  • C 端可见可互动： C 端用户能够在测评列表页浏览已上架帖子，点击进入详情页查看正文，并执行点赞、收藏、转发操作。
  • 总后台可配可控： 总后台操作人员可配置多个发布人形象，创建并管理测评帖子，控制上下架状态。

🔍业务背景
当前环节：① 配置发布人形象（头像 + 名称）

页面路径：SaaS 总后台 > 内容运营 > 测评 > 发布人设置

对下游影响：配置的发布人供帖子创建时选择，发布人头像和名称将展示在 C 端详情页中

表格类型：页面编辑类
⚙列表交互
交互：[新增发布人]

业务用途：新增一条发布人记录。点击后弹出新增抽屉，填写头像和名称，保存后发布人可被帖子引用。


交互：[编辑发布人]

业务用途：修改已有发布人的头像或名称。修改后所有已关联该发布人的历史帖子在 C 端同步展示最新头像和名称。


交互：[删除发布人]

业务用途：删除发布人记录。删除前需校验是否仍有已上架帖子关联该发布人；如有则提示不可删除，需先更换帖子发布人或下架帖子。
💡业务逻辑
新增时字段校验： 头像和名称均为必填，保存时校验不可为空。

删除保护： 发布人被已上架帖子引用时不可删除，提示"该发布人已被 X 篇已上架帖子引用，请先更换发布人或下架帖子后再删除"。被已下架帖子或未引用时可直接删除。

修改即时生效： 修改发布人头像或名称后，C 端所有关联该发布人的帖子（含历史和未来）均立即展示最新头像和名称，不保留历史快照。

🔍业务背景
当前环节：② 创建并上架测评帖子

页面路径：SaaS 总后台 > 内容运营 > 测评 > 帖子管理

对下游影响：上架后的帖子将出现在 C 端测评列表页，供用户浏览和互动

表格类型：列表页
⚙列表交互
交互：[新增帖子]

业务用途：新增一篇测评帖子。点击后打开新增抽屉，填写全部字段。保存时：如未选发布人则随机挑选一个；起始点赞数和起始收藏数如未填则各自随机赋值 400~900。


交互：[编辑帖子]

业务用途：修改已有帖子的任意字段。编辑后 C 端立即展示最新内容。排序、主图、标题、发布人、起始点赞数、起始收藏数、详情文本和上下架状态均可修改。


交互：[删除帖子]

业务用途：删除帖子记录。已上架的帖子需先下架再删除，或二次确认后直接删除（删除后 C 端不可见）。


交互：[上架 / 下架]

业务用途：切换帖子上下架状态。上架后帖子出现在 C 端测评列表；下架后 C 端不可见。用户在详情页浏览时被下架，页面 Toast 提示"内容已下架"并自动返回列表。


交互：[详情查看]

业务用途：点击表格行「详情」按钮打开详情抽屉，展示全部字段的完整值，包括详情文本的富文本渲染。
💡业务逻辑
排序规则： 数值越大越靠前。C 端列表按排序值降序展示。排序值相同的帖子，按创建时间倒序排列。

发布人随机规则： 新增或编辑帖子保存时，若发布人字段为空，系统从全部已配置发布人中随机抽取一个。如果当前无任何发布人，保存失败并提示"请先配置发布人"。

起始互动数随机规则： 起始点赞数未填 → 随机 400~900（含两端）；起始收藏数未填 → 随机 400~900（含两端）。两个随机值独立计算，不要求相同。

下架不可见： 帖子下架后，C 端列表不再展示该帖子，详情页也不可访问（直接访问详情链接时提示"内容已下架"）。

删除保护： 已上架帖子点击删除时，应弹出二次确认"该帖子当前为上架状态，删除后 C 端将不可见，确认删除？"。已下架帖子可直接删除。
