1.1 为什么要做

某 SaaS 平台为商家提供小程序服务，当前所有客户使用统一版本的小程序。现需要支持两件事：

1. 内部版本隔离：平台存在一个内部使用的小程序版本，与普通客户版本区分，发布代码时需有明确标识。

2. 推广路径可配置：客户推送给 C 端用户的链接需要支持多套推广路径，同一个页面下可有多个活动卡片，不同用户根据其身上写死的参数走向不同的页面和活动内容。

text
改造前

所有客户共用一套小程序版本，推广链接固定不可配置，
无法区分内部/外部版本，也不支持按用户参数分流到不同活动页面。


改造后

SaaS 总后台发布代码时标记内部版本
        ↓
管理 A/B 参数映射规则（A=渠道参，B=页面参），维护 2 张配置表
        ↓
商户运营人员在后台配置推广路径（推广位 + 页面类型 + 版位内容）
        ↓
系统生成带推广位 ID 和页面 ID 的推广路径
        ↓
C 端用户通过链接参数（A=渠道参，B=页面参）进入对应活动页面（未匹配时走默认兜底）

        +

        ↓

1.3 最终目标

  • 推广路径可配置： 商户运营人员能够在后台为每个推广位配置美团、饿了么或 B 版权益页下的活动版位内容，系统自动生成推广路径，C 端用户按参数分流进入对应活动页面。
  • 内部版本可识别： SaaS 总后台发布代码时，内部版本小程序具备明确标识，与普通客户版本区分，两套版本各自独立管理推广路径。

3.1 内部版本标识与参数映射 — 内容页

业务背景

当前环节：① 发布小程序代码，标记内部版本标识；② 管理 A/B 参数映射

页面路径：SaaS 总后台 > 代码发布管理

对下游影响：参数映射规则决定 C 端用户打开推广链接后进入哪个页面和活动

一、基本定义与前提

参数 含义 说明
A 渠道参 决定用户走哪套推广链接（链接套系），写死在用户身上
B 页面参 决定用户进入哪种页面类型：0/缺省、3（美团）、5（饿了么）、7（B版权益页）

现有配置表： 共有 2 张表——

表 名称 用途
表1 权益页面的链接配置表 B=0 或缺省时检索此表
表2 专题页的配置表 B=3、5、7 时检索此表（即 4.1 推广路径管理页）

核心场景： 用户收到了一条推广链接，携带了 A（渠道参）和 B（页面参）。系统按下方分支逻辑决定展示内容。

二、详细分支逻辑

1. 分支一：B = 0（或缺省）、3、5、7（用户覆盖 B 标签）

用户身上已有 B 参数标签（由历史推广链接写入）。系统根据 B 值选择检索哪张表。

text
用户收到推广链接（携带 A=渠道参, B=页面参）
        │
        ├── B = 0 / 3 / 5 / 7（用户覆盖 B 标签）
        │        │
        │        ├── ❶ B=0（或缺省）→ 检索"权益页表1"
        │        │        ├── A 在表内 → A 对应的全套链接，覆盖 A 标签
        │        │        └── A 不在表内 → 表1「默认链接」的全套链接，不更新 A
        │        │
        │        ├── ❷ B=3（美团）→ 检索"专题页表2"
        │        │        ├── A 在表内 → A 对应的全套链接，覆盖 A 标签
        │        │        └── A 不在表内 → 表2「默认链接」的 B=3 全套链接，不更新 A
        │        │
        │        ├── ❸ B=5（饿了么）→ 检索"专题页表2"
        │        │        ├── A 在表内 → A 对应的全套链接，覆盖 A 标签
        │        │        └── A 不在表内 → 表2「默认链接」的 B=5 全套链接，不更新 A
        │        │
        │        └── ❹ B=7（B版权益页）→ 检索"专题页表2"
        │                 ├── A 在表内 → A 对应的全套链接，覆盖 A 标签
        │                 └── A 不在表内 → 表2「默认链接」的 B=7 全套链接，不更新 A
        │
        └── B 不等于 0、3、5、7
                 └── 按用户头上旧 A 和旧 B 的全套链接，不更新

标签更新规则：A 在配置表内 → 用户覆盖 A 标签（后续访问使用新 A）；A 不在表内 → 不更新 A 标签（保留旧值）。

内部版本标识规则：

SaaS 总后台在每次发布小程序代码时，需对内部版本进行显式标记：

  • 内部版本的小程序在发布时带有内部标识字段，供客户端识别。
  • 同一套推广路径配置在内部版本和普通版本中各自独立。
  • 内部版本主要用于平台内部测试、演示或特殊运营场景，不面向普通 C 端用户开放。

5.1 链接参数规则

  • A 参数（链接套系）： 决定用户走哪套推广链接。同一推广位下可能存在多个活动卡片组合，A 参数用于选择具体的链接套系。该参数写死在用户身上，用户接触新的推广链接前不会变更。
  • B 参数（页面参）： 决定用户进入哪种页面类型。B=3（美团）、B=5（饿了么）、B=7（B版权益页）→ 检索专题页表2；B=0 或缺省 → 检索权益页表1。
  • 参数绑定： A 和 B 参数通过推广链接写入用户画像。A 在表内匹配成功时覆盖旧值，未匹配时保留旧值。后续访问持续使用已写入的参数。

5.2 推广路径匹配规则

  • C 端用户打开推广链接时，系统根据用户身上的 B 参数确定检索哪张表（B=0或缺省→权益页表1；B=3/5/7→专题页表2），再结合 A 参数匹配对应配置。
  • 若 A 参数在表内未匹配到，走对应表的「默认链接」兜底。
  • 若匹配到推广路径但对应版位未配置内容，该版位不展示（不影响已配置版位的正常展示）。

5.3 内部版本规则

  • 内部版本的小程序在 SaaS 总后台发布代码时标记内部标识。
  • 内部版本和普通版本的推广路径配置相互独立，商户在各自版本的后台配置仅对当前版本生效。
  • 普通 C 端用户无法访问内部版本的小程序。

🔍业务背景

页面路径：客户端后台 > 推广管理 > 推广路径配置

对下游影响：配置完成后生成推广路径（推广位 ID + 页面 ID），C 端用户通过携带 A/B 参数的链接进入小程序时，系统根据用户身上的参数匹配对应推广路径，渲染对应版位活动内容

表格类型：列表页


推广路径管理页面是商户运营人员配置小程序推广内容的核心入口。页面以列表形式展示所有已配置的推广路径，支持新增、编辑、删除和查看详情。其中推广位和页面类型共同构成推广路径的唯一标识，新增时选定后不可再改。

页面上方提供筛选下拉（全部 / 美团 / 饿了么 / B版权益页），按页面类型过滤列表数据。
⚙列表交互
交互：新增推广路径

业务用途： 打开新增抽屉，商户按"基本信息 → 版位配置"分组依次填写（B=3/5 为上下版位，B=7 为分类列表）。页面类型下拉切换时联动预览图（美团黄 / 饿了么蓝 / B版权益页红）并切换版位布局。保存后系统自动生成推广路径（推广位 ID + 页面 ID），记录出现在列表顶部，状态为"已配置"。推广位和页面类型在新增时选定后不可再改。

交互：编辑推广路径

业务用途： 打开编辑抽屉，预填已有配置。推广位和页面类型不可编辑（置灰）。商户可修改备注、上下版位的跳转方式及相关字段。跳转方式切换时联动置灰对应字段组（小程序 → AppID+路径可用，URL 置灰；H5 → URL 可用，AppID+路径置灰）。保存后更新最近修改时间。已生成的推广路径不变（推广位 ID 和页面 ID 未变）。

交互：查看详情

业务用途： 打开详情抽屉，按"基本信息 / 上版位配置 / 下版位配置"三组展示全部配置信息。未配置的版位对应字段显示"—"。跳转摘要按实际跳转方式格式化展示。

交互：删除推广路径

业务用途： 二次确认后删除该条推广路径配置。删除后 C 端对应推广位的该页面类型将不再展示配置的活动内容（回退为默认行为）。已产生的历史点击数据不受影响。
💡业务逻辑
页面类型与 B 参数映射： 页面类型决定 B 参数值。美团对应 B=3，饿了么对应 B=5，B版权益页对应 B=7。B=0 或缺省时检索权益页表1。

推广路径生成规则： 保存配置时，系统自动拼接推广位 ID 和页面 ID 生成推广路径，格式为"[推广位ID]_[页面ID]"。其中页面 ID 对应 B 参数值（美团=3，饿了么=5，B版权益页=7）。推广路径是下游链接拼装的唯一依据。

编辑不可改键： 编辑时推广位和页面类型不可修改，因为二者共同构成推广路径的唯一标识（唯一键）。如需更换推广位或页面类型，需删除当前记录后重新新增。

上下版位独立配置： 上版位和下版位各自独立配置，互不影响。允许仅配置上版位、仅配置下版位，或两者都配置。C 端渲染时，未配置的版位不展示。

筛选与预览： 列表页提供页面类型筛选下拉（全部 / 美团 / 饿了么 / B版权益页），筛选后仅展示对应页面类型的推广路径。页面类型对应不同的主题色标识（美团黄、饿了么蓝、B版权益页红），用于列表卡片和预览图的视觉区分。
