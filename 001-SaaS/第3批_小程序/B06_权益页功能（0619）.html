B06 权益页功能

本功能是 SaaS 平台的页面搭建能力。开发团队预编译组件模板，SaaS 总后台管理组件上下架和跳转配置，商户在客户端拖拽组件搭建权益页，C 端用户访问权益页并点击组件参与活动。 当前负责组件库管理、可点击组件跳转配置、默认样式维护和商户权益页编辑。不涉及活动内容本身的管理和推广链接的生成。

1. 需求背景与目标

1.1 为什么要做

商户需要一个面向 C 端用户展示权益活动的落地页，页面由多个组件拼装而成。在系统建设前，页面搭建依赖开发介入，运营和商户无法自主调整页面内容和布局。

本功能通过三层职责分离实现页面搭建的自治：开发团队一次性预编译组件模板，运营自主管理组件上下架和跳转目标，商户通过纯拖拽方式搭建自己的权益页。

改造前

开发写死页面布局 → 运营无法调整可用组件 → 商户无法自主搭建权益页


改造后

开发预编译组件模板
        ↓
运营管理组件上下架 + 配置可点击组件的跳转目标 + 设置默认样式
        ↓
商户从组件库拖拽组件 → 排列布局 → 保存权益页
        ↓
C 端用户访问权益页 → 点击组件参与活动

1.2 一句话业务模型

开发预编译的组件模板（HTML + CSS）
        +
运营在总后台管理组件启用/禁用 + 配置可点击组件的跳转目标
        +
商户在客户端拖拽组件搭建权益页
        ↓
C 端用户访问权益页 → 点击可点击组件 → 跳转 H5 活动页或第三方小程序

1.3 最终目标

本功能首先保证商户能够自主搭建可用的权益页，使 C 端用户能够通过权益页参与推广活动；其次降低运营和开发的维护成本；最后通过组件模板和默认样式统一页面规范。

核心业务目标：商户自主搭建 + 用户可参与

  • 商户自主搭建权益页： 商户无需技术能力，通过拖拽即可完成页面搭建和更新。
  • C 端用户可点击参与： 用户访问权益页后，点击可点击组件进入对应活动，形成推广转化。
  • 配置变更实时生效： 运营修改组件跳转目标后，所有使用该组件的权益页实时反映最新配置。

经营效率目标：减少运营和开发维护成本

  • 组件上下架无需开发介入： 运营通过开关控制组件对商户的可见性。
  • 商户从组件库自选： 商户从已启用组件中自由选择，不需要运营逐个配置。
  • 默认样式降低上手门槛： 新商户注册后自动获得预设布局，无需从空白画布开始。

平台支撑目标：统一页面规范和配置规则

  • 组件模板统一管理： 所有组件的 HTML 和 CSS 由开发团队预编译，保证样式一致。
  • 跳转目标由运营统一配置： 商户不可修改组件的跳转地址，避免配置错误。
  • 默认样式集中维护： 一套默认布局统一应用于所有新注册商户。

3. 第一阶段：组件与默认样式准备

3.1 阶段说明

本阶段由 SaaS 总后台运营完成。运营在组件库列表中管理所有已注册组件的启用状态，为可点击组件配置跳转目标，并设置一套默认样式供新商户注册时自动应用。

组件模板本身由开发团队预编译并注册到系统，运营不参与组件代码的编写和修改。

本阶段主要包括：

  1. 查看组件库列表，切换组件的启用/禁用状态。
  2. 为可点击组件选择跳转目标活动。
  3. 配置新商户默认样式。

3.2 组件库列表

流程位置

①【开发团队】预编译组件模板并注册到系统
↓
②【SaaS 总后台】进入组件库列表（当前位置）
↓
③【SaaS 总后台】启用/禁用组件，或编辑可点击组件的跳转配置

功能使命

组件库列表是运营管理所有组件的一览入口。运营在此查看已注册组件、切换启用状态，并对可点击组件发起跳转配置。

页面说明

SaaS 总后台 / 页面管理 / 组件库管理

页面顶部按组件类型提供筛选 Tab（全部 / 标题 / 链接），每个 Tab 显示对应数量。列表展示组件的缩略预览图、名称、类型标签和启用开关。

标题类型组件仅显示启用开关，无可配置项。链接类型组件额外显示「编辑」按钮，用于配置跳转目标。

展示字段

字段 显示内容 来源 用途
组件预览 组件缩略图 开发预编译时提供 辅助识别组件样式
组件名称 开发定义的组件名称 当前组件 识别组件
组件类型 标题或链接 当前组件 区分是否可点击和是否可配置
启用状态 启用或禁用 当前组件 控制组件对商户是否可见

列表操作

操作 当前结果 业务用途
切换启用开关 组件状态即时更新，商户端组件库同步变化 控制组件可用范围
编辑（仅链接组件） 打开跳转配置弹窗 为可点击组件选择目标活动

已明确的规则：

  • 标题组件不显示编辑按钮，仅可切换启用/禁用。
  • 启用状态切换即时生效，无需额外保存。
  • 禁用组件后，已使用该组件的商户画布不受影响，但商户不可再新拖入该组件。

3.3 编辑可点击组件的跳转配置

流程位置

①【SaaS 总后台】在组件库列表中
↓
② 点击链接组件的「编辑」按钮
↓
③【SaaS 总后台】在弹窗中选择目标活动（当前位置）
↓
④ 系统自动判定跳转方式并显示预览
↓
⑤ 保存配置

功能使命

为可点击组件绑定一个目标活动。C 端用户点击该组件后，系统根据活动属性自动判定跳转方式（跳 H5 活动页或跳小程序），运营无需手动选择跳转平台。

活动可选条件

弹窗中的活动下拉列表只显示满足以下任一条件的活动（取并集）：

条件 说明 跳转方式
活动已配置小程序路径 活动具备可跳转的小程序目标页面 跳转小程序
活动已开启口令自动更新且配置了 H5 页面地址 两个条件必须同时满足 跳转 H5 活动页
活动类型为第三方活动 来自第三方活动管理的全部活动 跳转小程序

不满足任一条件的活动不出现在下拉列表中。若运营找不到想要的活动，需引导其先去活动管理或第三方活动管理页面补充配置。

跳转方式自动判定

选中活动后，系统根据活动满足的条件自动确定跳转方式，并在弹窗底部显示跳转预览提示：

  • 活动满足"口令自动更新 + H5 页面地址"→ 跳转 H5，预览显示"跳转至「活动 H5 名称」（H5 活动页）"。
  • 活动满足"有小程序路径"或"第三方活动"→ 跳转小程序，预览显示"跳转至「平台名称」平台下的小程序"。

运营无需手动选择跳转平台。若同一活动同时满足多个条件，H5 跳转优先。

配置字段

字段 填写或选择内容 用途
选择活动 从满足过滤条件的活动下拉列表中选择 绑定组件的跳转目标

保存后配置即时生效。已使用该组件的所有商户权益页在 C 端展示时，均读取最新的跳转目标。

3.4 配置默认样式

流程位置

①【SaaS 总后台】在组件库列表中
↓
② 点击「配置默认样式」按钮
↓
③【SaaS 总后台】勾选组件并排序（当前位置）
↓
④ 保存默认样式 → 新商户注册时自动应用

功能使命

运营预设一套默认的权益页布局。新商户注册成功后，系统自动将默认样式写入商户画布，使权益页自带初始配置。商户可在此基础上增删改，无需从空白画布开始搭建。

配置规则

  • 仅显示已启用的组件。
  • 标题组件始终可勾选。
  • 链接组件：已配置跳转目标的正常可选；未配置跳转目标的链接组件置灰显示，不可勾选。
  • 已勾选的组件支持上下拖拽排序，排序结果即为默认画布的组件顺序。
  • 同一组件在默认样式中最多出现一次。

生效规则

  • 默认样式仅在新商户注册时自动应用一次。
  • 已注册商户的画布不受默认样式变更影响。
  • 默认样式修改后，后续新注册商户使用最新版本。
  • 若未配置默认样式，新商户的权益页初始为空画布。

4. 第二阶段：商户配置权益页

4.1 阶段说明

商户进入权益页编辑器，从左侧组件库中查看已启用的组件，拖拽组件到中间手机模拟器画布，调整排列顺序，保存后完成权益页搭建。

商户不可编辑组件的内部内容（标题文案、跳转目标、样式等均由开发预编译或运营配置）。商户仅控制画布中有哪些组件、以什么顺序排列。

↓
②【客户端后台】进入权益页配置编辑器（当前位置）
↓
③ 从组件库拖拽组件到画布
↓
④ 调整组件排列顺序
↓

区域 内容

分组 内容来源 说明

拖拽操作

操作 结果

已保存 当前布局已持久化 点击保存后

5. 第三阶段：C 端展示与点击

5.1 阶段说明

C 端用户通过商户投放的入口访问权益页。页面按商户保存的画布布局展示组件。用户可上下浏览所有组件，点击可点击组件后跳转至对应活动。

5.2 C 端权益页展示

流程位置

①【客户端后台】保存权益页布局
↓
②【C 端用户】访问权益页（当前位置）
↓
③ 浏览组件内容
↓
④ 点击可点击组件 → 跳转活动

展示规则

  • 页面按商户画布中保存的组件顺序自上而下展示。
  • 标题组件仅展示标题文案和图标，无点击响应。
  • 可点击组件展示活动名称、平台标签和缩略图，点击后触发跳转。
  • 跳转目标读取运营在总后台为该组件配置的最新活动，实时生效。

跳转行为

组件绑定的活动类型 用户点击后

6. 关键业务规则

6.1 三层职责分离

  • 开发团队预编译组件模板（HTML 模板 + CSS 样式），并注册到系统。
  • SaaS 总后台运营管理组件的启用/禁用状态，配置可点击组件的跳转目标，设置默认样式。
  • 客户端商户从已启用组件中拖拽选择，排列布局，保存权益页。
  • 商户不可编辑组件的内部内容（标题文案、样式、跳转地址）。
  • 各层只做自己权限范围内的事，不越界。

6.2 组件分类

分类 子类型 可点击 总后台可配置
标题组件 一级标题、二级标题、三级标题 否 仅启用/禁用
链接组件 大卡片、小卡片、横幅 是 启用/禁用 + 跳转目标活动

6.3 活动过滤与跳转判定

可点击组件可选的活动范围取三种条件的并集：

  1. 活动已配置小程序路径。
  2. 活动已开启口令自动更新且配置了 H5 页面地址（两个条件需同时满足）。
  3. 活动类型为第三方活动。

跳转方式由活动自身属性自动判定：条件 2 的活动跳转 H5，条件 1 和 3 的活动跳转小程序。运营无需手动选择跳转平台。

6.4 配置变更的生效范围

  • 运营修改组件跳转目标后，所有已使用该组件的权益页实时读取最新配置，无需商户重新保存。
  • 运营禁用组件后，已使用该组件的商户画布不受影响，仅阻止新拖入。
  • 默认样式变更不影响已注册商户的既有画布，仅对新注册商户生效。

  • 未确认的字段格式、权限细节、通知和重试规则只保留在「待确认逻辑」。

8.2 模块边界

  • 本模块负责：组件库的启用管理、可点击组件的跳转配置、默认样式的设置与应用、商户权益页的拖拽编辑和保存。
  • 上游模块：活动管理-联盟提供联盟活动数据，活动管理-第三方提供第三方活动及路径，口令自动更新为活动提供 autoRefreshToken 标记。
  • 下游模块：C 端权益页渲染和点击跳转的承接。
  • H5 活动页在小程序内嵌打开时，依赖小程序基础配置中的 H5 内嵌业务域名。

8.6 待确认逻辑

  1. 组件缩略图的设计规范（尺寸、格式）是否已有明确要求？
  2. 运营修改链接组件的跳转目标后，已保存布局中的历史配置是否需要保留快照，还是始终读取最新值？
  3. 画布中组件的双列布局（左列/右列）是否需要商户手动指定列位置？
  4. 一个活动后续不再满足任何过滤条件时，已配置了该活动的组件是否需要标记异常状态？
  5. C 端权益页的页面标题来源是什么（商户设置、默认标题还是系统生成）？
  6. 商户删除画布中所有组件后保存，C 端展示空页面还是显示默认占位内容？
  7. 是否存在更细的后台角色权限（如运营管理员与普通运营的权限区分）？
  8. 是否需要操作日志记录组件的启用/禁用、跳转配置修改和默认样式变更？
