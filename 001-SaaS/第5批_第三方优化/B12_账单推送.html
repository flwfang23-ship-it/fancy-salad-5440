1.1 为什么要做

常规账单、激励账单和合并账单可由账单系统归集生成。无法自动归集的账单由总后台通过 Excel 批量新建。

6.1 客户归属

  • 系统生成账单必须完成客户归属后，才能进入财务审核。
  • 系统生成账单的 SaaS ID 为 0 时，不进入审核流程。
  • Excel 新建账单在导入时直接选择 SaaS 客户，导入成功即形成待审核账单。

6.2 审核与送达

  • 系统生成账单和 Excel 新建账单统一进入财务审核。
  • 财务审核只有"审核通过、删除、修改"三个操作，没有驳回或不通过逻辑。
  • 修改仅允许调整业务类型、佣金金额、调账金额和预发月结金额。
  • 所有账单只有审核通过后才能送达客户。
  • 删除的账单不送达客户。
  • 客户只能查看归属于当前客户且已经送达的账单。

📋业务背景

当前环节：④⑤⑥⑦⑧ 进入账单列表、Excel 导入并选择客户、形成待审核账单、财务审核、送达客户

页面路径：SaaS 总后台 > 财务管理 > 账单核对

对下游影响：审核通过的账单送达对应客户后，客户在客户端后台可见并可进入后续提现流程。

SaaS 总后台账单管理页面是两类账单汇合后的统一处理入口。财务人员在此查看所有待审核账单，通过 Excel 新建无法自动归集的账单，并在账单送达客户前完成修改、删除或审核通过。

⚡列表交互

Excel 导入新建：批量新建无法自动归集的账单并直接选择客户。导入成功后形成具有明确客户归属的待审核账单，进入同一待审核列表。

查看详情：展示当前账单的完整信息，包括账单单号、客户归属、账单时间、业务类型、订单数、金额构成、审核与送达状态及账单文件。仅用于审核和追溯。

修改：在账单送达客户前，编辑业务类型、佣金金额、调账金额和预发月结金额。保存后仍为待审核账单，可继续审核通过或删除。

删除：删除当前账单，终止该账单。删除后不送达客户，不进入客户端账单列表。

审核通过：确认账单内容无误后审核通过，账单进入送达流程。

送达：将审核通过的账单送达对应客户，客户在客户端后台可见该账单。

🧠业务逻辑

系统生成账单必须先完成客户归属：来自账单系统的账单，只有归属成功的才能进入待审核列表。SaaS ID 为 0 的不进入。

Excel 导入即确定归属：Excel 新建账单在导入时必须选择 SaaS 客户，导入成功即形成待审核账单。

两类账单审核与送达规则完全相同：系统生成和 Excel 新建进入同一待审核列表后，审核和送达规则不再区分来源。

修改仅限指定字段：除业务类型、佣金金额、调账金额和预发月结金额外，财务审核环节不修改其他账单业务字段。

审核通过是送达前置条件：所有账单只有审核通过后才能送达客户。删除的账单不送达客户。

详情不重新计算：账单详情只展示当前账单的完整信息，不重新计算金额，也不重新处理客户归属。

📋业务背景

当前环节：⑨⑩ 查看账单、进入提现流程

页面路径：客户端后台 > 财务结算 > 账单

对下游影响：客户从此进入 B13 提现流程，沿用已送达账单的结算金额，不在提现环节重新形成账单。

客户端后台账单列表向客户展示已经送达的账单，帮助客户识别结算期间、核对结算金额，并提供进入后续提现流程的入口。客户不需要区分账单来自系统归集还是 Excel 新建。

账单送达和提现是前后衔接的两段业务：B12 负责形成账单、完成财务审核并送达客户；B13 负责收款配置、可提现范围、提现申请、审核和打款。

⚡列表交互

查看详情：展示当前账单的完整信息，包括客户名称、客户 ID、业务类型、金额构成和账单文件。用于核对账单时间、金额构成和业务类型。

进入提现：基于当前账单发起提现申请，进入 B13 提现流程。

🧠业务逻辑

客户只能看到本人已送达账单：客户登录后仅展示归属于当前客户且 SaaS 总后台已送达的账单。未送达或已删除的账单不可见。

详情与列表同源：详情和列表引用同一张已送达账单记录，详情不重新计算金额。

客户无需区分账单来源：系统生成账单和 Excel 新建账单送达后，在客户端展示完全一致，客户不需要也不展示区分。
