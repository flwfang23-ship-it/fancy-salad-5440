需求背景与目标

1.1 为什么要做

我们的业务需要把总后台域名池中的域名，关联到企业微信主体下的自建应用，再由客户端（推精灵）读取关联结果并生成推广链接，用于跟踪哪些企微用户访问了推广内容。整个链路横跨三个操作端：

  • 总后台（域名池）：维护一批可用于推广的域名，并将域名关联到企业微信自建应用。
  • 企业微信管理后台：在企业微信主体下创建自建应用，并把域名绑定到自建应用的「网页授权及 JS-SDK」。
  • 客户端（推精灵）：回显已关联的自建应用信息，运营人员据此生成推广链接并投放。

由于投诉链接和正常推广链接需要区分处理，企业微信侧必须创建两个自建应用分别承载，避免投诉与正常推广的域名、授权范围、数据统计互相干扰。

1.3 最终目标

  • 域名与应用一一关联：总后台域名池中的每个域名都关联到对应的企业微信自建应用，投诉类域名关联投诉自建应用，正常推广类域名关联正常推广自建应用。
  • 两个自建应用就位：企业微信主体下创建「投诉」和「正常推广」两个自建应用，各自绑定一个域名，互不干扰。
  • 客户端可回显与推广：客户端（推精灵）能自动回显已关联的自建应用信息，运营人员可直接取推广链接投放，并能看到哪些企微用户进行了访问。

域名池管理

①当前环节：① 域名池管理
页面路径总后台 > 域名池管理
对下游影响域名池是整个关联链路的起点，域名的可用性、类型（投诉/正常推广）直接决定后续可关联的自建应用范围。

域名池的作用

域名池维护了一批可用于推广的域名，每个域名有独立的类型标签（投诉类 / 正常推广类）。后续关联企业微信应用时，投诉类域名只能关联到「投诉」自建应用，正常推广类域名只能关联到「正常推广」自建应用，避免混用。

关键字段

  • 域名：如 cnh5.feizhangquan.com，用途为推广链接的承载域名。
  • 类型：投诉 / 正常推广，用途为限制该域名可关联的自建应用类型。
  • 状态：可用 / 已占用 / 停用，用途为标识域名是否可被关联。
  • 是否启用：开关，用途为控制域名是否可用于生成推广链接。

注意事项与坑点

  • 域名类型不要标错：投诉类域名标成正常推广，会导致投诉链接走正常推广应用，数据统计口径混乱。
  • 停用域名不可关联：已停用的域名无法关联到自建应用，如需使用请先启用。
  • 一个域名只能关联一个应用：域名与自建应用是一对一关系，已关联的域名不能重复关联。

业务逻辑

域名池是关联链路的起点：总后台先维护好可用域名并标记类型，后续才能进入 3.2 将域名关联到企业微信自建应用。域名的类型标签决定了它能关联到哪类自建应用，这是避免投诉与正常推广混用的第一道防线。

域名关联企业微信应用

②当前环节：② 域名关联企微应用
页面路径总后台 > 域名池管理 > 操作列 > 关联应用
对下游影响关联后，该域名与企业微信自建应用建立映射关系，作为第二阶段在企业微信后台绑定域名的依据；同时客户端后续回显的关联信息也来源于此。

关联操作步骤

1. 登录总后台，进入「域名池管理」页面。

2. 在域名列表中找到要关联的域名，点击操作列的「关联应用」按钮。

3. 在弹出的关联窗口中，选择该域名要关联的企业微信自建应用：

  • 投诉类域名 → 选择「投诉」自建应用
  • 正常推广类域名 → 选择「正常推广」自建应用

4. 确认关联信息无误后，点击「确定」完成关联。

5. 关联成功后，该域名的关联状态更新为「已关联」，并显示关联的自建应用名称。

截图参考：总后台域名池列表中，操作列提供「关联应用」入口（红框标注）。

关键字段

  • 域名：来源为域名池列表；用途为关联关系的主体。
  • 关联的自建应用：来源为下拉选择（投诉 / 正常推广）；用途为建立域名与应用的映射。
  • 关联状态：来源为系统自动更新；用途为标识域名是否已关联应用。

注意事项与坑点

  • 类型必须匹配：投诉类域名只能关联「投诉」自建应用，正常推广类域名只能关联「正常推广」自建应用，系统会校验类型是否匹配。
  • 关联后不可随意修改：已关联的域名如需更换应用，需先解除关联再重新关联，避免线上推广链接突然失效。
  • 关联不等于绑定：本步骤只是在总后台建立域名与应用的映射关系，真正的域名绑定需要在第二阶段到企业微信管理后台完成。

业务逻辑

关联是绑定的前置条件：总后台的关联操作建立了"哪个域名对应哪个自建应用"的映射，但此时域名尚未真正绑定到企业微信自建应用上。必须完成第二阶段的企业微信后台绑定后，客户端才能正常回显关联信息并生成推广链接。

创建两个自建应用

③当前环节：③ 创建两个自建应用
页面路径企业微信管理后台 > 应用管理 > 自建
对下游影响自建应用是域名绑定和推广链接授权的载体，必须创建「投诉」和「正常推广」两个应用分别承载两类业务，避免投诉与正常推广的域名、授权范围、数据统计互相干扰。

为什么需要两个自建应用

企业微信的一个自建应用只能绑定一个域名（网页授权及 JS-SDK 限制），且应用的可见范围、可信域名、数据统计相互独立。投诉链接和正常推广链接的业务诉求不同：

  • 投诉自建应用：承载投诉类域名，用于用户提交投诉、反馈问题。
  • 正常推广自建应用：承载正常推广类域名，用于推广活动、引导用户访问。

如果只用一个自建应用，投诉和正常推广会共用同一个域名和授权范围，无法区分数据统计口径，也不利于权限隔离。因此必须创建两个独立的自建应用。

创建操作步骤

1. 登录企业微信管理后台 https://work.weixin.qq.com/，进入「应用管理」。

2. 在「自建」区域点击「创建应用」。

3. 填写应用信息：

  • 应用名称：投诉（或正常推广）
  • 应用 logo：上传对应图标
  • 可见范围：选择需要使用该应用的部门/成员

4. 点击「创建应用」完成第一个自建应用的创建。

5. 重复上述步骤，创建第二个自建应用（正常推广 / 投诉）。

6. 创建完成后，在自建应用列表中能看到「投诉」和「正常推广」两个应用。

关键字段

  • 应用名称：用途为区分两个自建应用，建议明确命名为「投诉」「正常推广」。
  • AgentId：来源为企业微信自动生成；用途为调用企业微信 API 时的应用标识。
  • Secret：来源为企业微信自动生成；用途为应用接口调用凭证，需妥善保管。
  • 可见范围：用途为控制哪些成员可在企业微信中看到该应用。

注意事项与坑点

  • 必须创建两个：不要图省事只建一个，投诉和正常推广必须分开，否则数据无法区分。
  • 可见范围按需设置：只把需要使用该应用的成员加入可见范围，避免无关成员看到。
  • Secret 妥善保管：Secret 是应用接口调用的凭证，泄露后可能被他人冒用，不要明文传播。
  • 应用名称不要混淆：两个应用名称要明确区分，避免后续绑定时把域名绑错应用。

业务逻辑

两个应用 = 两条独立链路：投诉和正常推广各自拥有独立的自建应用、独立的域名、独立的授权范围和独立的数据统计。这种隔离确保了投诉数据不会混入正常推广数据，也方便后续针对两类业务做独立的权限控制和数据分析。

自建应用绑定域名

④当前环节：④ 自建应用绑定域名
页面路径企业微信管理后台 > 应用管理 > 自建 > 对应应用 > 网页授权及 JS-SDK
对下游影响绑定后，该域名成为自建应用的可信域名，客户端生成的推广链接才能正常完成网页授权和 JS-SDK 调用，企微用户访问推广链接时才能被正确识别。

绑定操作步骤

1. 登录企业微信管理后台，进入「应用管理」>「自建」。

2. 点击要绑定域名的自建应用（投诉 / 正常推广）。

3. 在应用详情页找到「网页授权及 JS-SDK」区域，点击「设置」。

4. 在可信域名输入框中，填入总后台已关联到该应用的域名（如 cnh5.feizhangquan.com）。

5. 点击「保存」完成绑定。

6. 重复上述步骤，为另一个自建应用绑定对应的域名。

截图参考：企业微信自建应用详情页中，「网页授权及 JS-SDK」区域用于绑定域名，红框标注处提示"一个自建应用只能绑定一个域名"。

关键字段

  • 可信域名：用途为自建应用的网页授权和 JS-SDK 调用域名，一个自建应用只能绑定一个。
  • 应用主页：可选，用途为设置应用的默认跳转页面。

注意事项与坑点

  • 一个自建应用只能绑定一个域名：这是企业微信的硬性限制，不要尝试在一个应用下绑定多个域名。
  • 域名必须与总后台关联的一致：企业微信后台绑定的域名必须与总后台 3.2 中关联到该应用的域名一致，否则客户端回显和推广链接生成会失败。
  • 域名需已备案：企业微信要求可信域名必须已完成 ICP 备案，未备案域名无法绑定。
  • 绑定后不要随意修改：线上推广链接依赖该域名，修改域名会导致已投放的推广链接失效。
  • 两个应用分别绑定：投诉应用绑定投诉类域名，正常推广应用绑定正常推广类域名，不要交叉绑定。

业务逻辑

绑定是关联生效的关键一步：总后台的关联只是建立了映射关系，企业微信后台的绑定才真正让域名获得网页授权和 JS-SDK 能力。只有完成绑定后，客户端生成的推广链接才能在企微环境内正常工作，企微用户访问时才能被正确识别和统计。

企微配置-关联信息回显

⑤当前环节：⑤ 企微配置-关联信息回显
页面路径客户端（推精灵） > 企微配置
对下游影响客户端自动回显已关联的自建应用信息（含企业名称、企业微信ID、服务器节点IP、自建应用授权URL、通讯录URL等），运营人员据此确认关联是否成功，并进行后续推广链接的生成。

回显内容说明

客户端「企微配置」页面的「自建应用」区域会自动回显已关联的自建应用信息，包括：

  • 数据ID：关联记录的唯一标识。
  • 企业名称：企业微信主体名称。
  • 企业微信ID：企业微信的 CorpID。
  • 服务器节点IP：关联应用所在的服务器节点。
  • 自建应用授权URL：用于企业微信授权回调的地址。
  • 通讯录URL：用于同步企业微信通讯录的地址。
  • 添加时间：关联记录创建时间。

截图参考：客户端企微配置页面中，「自建应用」表格回显了已关联的应用信息（红框标注），运营可在此确认关联状态。

确认关联成功的标志

  • 自建应用表格中有对应企业的记录。
  • 自建应用授权URL 和 通讯录URL 均已填充（非空）。
  • 服务器节点IP 已分配。

如果上述信息缺失，说明总后台关联或企业微信后台绑定未完成，需回到第一/二阶段排查。

注意事项与坑点

  • 回显依赖前两阶段完成：只有总后台关联 + 企业微信后台绑定都完成后，客户端才能回显完整信息。
  • 回显信息不要手动修改：回显内容由系统自动同步，手动修改可能导致关联失效。
  • 多个企业分别回显：如果有多个企业微信主体，每个主体的自建应用信息会分别回显，不要混淆。

业务逻辑

回显是关联成功的验收标志：客户端能回显完整的自建应用信息，说明总后台关联和企业微信后台绑定均已成功，域名与自建应用的映射关系已生效。运营人员确认回显无误后，即可进入下一步取推广链接投放。

取推广链接投放

⑥当前环节：⑥ 取推广链接投放
页面路径客户端（推精灵）> 推广管理 > 单活动H5
对下游影响运营人员从单活动H5列表中取「小程序链接」列的推广链接，投放到企微社群/朋友圈/好友等渠道，企微用户点击链接后即可被识别和统计。

取链接操作步骤

1. 登录客户端（推精灵），进入「推广管理」>「单活动H5」。

2. 在活动列表中找到要推广的活动。

3. 复制该活动「小程序链接」列对应的推广链接。

4. 将推广链接投放到企微社群、朋友圈、好友聊天等渠道。

5. 企微用户点击链接访问后，系统会记录访问用户的企微身份。

截图参考：客户端单活动H5列表中，「小程序链接」列即为推广链接（红框标注），运营复制后即可投放。

推广链接的构成

推广链接基于已关联的域名生成，格式通常为 http://<域名>/<路径>。域名部分对应总后台关联、企业微信绑定的可信域名，因此链接在企微环境内可正常完成网页授权。

注意事项与坑点

  • 取「小程序链接」列：不要取错列，单活动H5列表中有多列链接，推广用的是「小程序链接」列。
  • 链接基于已关联域名生成：只有域名关联并绑定成功后，生成的推广链接才能在企微环境内正常访问。
  • 投放渠道限企微生态：推广链接主要用于企微社群、朋友圈、好友等企微生态内渠道，投放到外部渠道可能无法识别企微用户身份。
  • 链接不要随意修改：推广链接的域名和路径由系统生成，手动修改可能导致授权失败。

业务逻辑

推广链接是关联链路的最终产出：经过总后台关联、企业微信绑定、客户端回显三步后，运营人员拿到的推广链接具备在企微环境内正常工作的能力。企微用户点击链接后，系统可识别其企微身份并记录访问行为，为后续数据分析提供基础。

查看访问的企微用户

⑦当前环节：⑦ 查看访问的企微用户
页面路径客户端（推精灵） > 数据统计 / 推广效果
对下游影响运营人员可查看每个推广链接被哪些企微用户访问过，包括访问时间、用户身份等，用于评估推广效果和跟进潜在客户。

可查看的信息

  • 访问用户：点击推广链接的企微用户昵称/姓名。
  • 访问时间：用户点击链接的具体时间。
  • 访问次数：同一用户的多次访问记录。
  • 所属活动：该用户访问的是哪个推广活动的链接。

数据来源说明

企微用户访问推广链接时，链接基于已绑定的可信域名完成网页授权，系统通过企业微信接口获取用户的企微身份信息，从而记录访问行为。这也是为什么必须完成企业微信后台域名绑定的原因——未绑定的域名无法完成网页授权，也就无法获取用户身份。

注意事项与坑点

  • 数据依赖网页授权：只有完成企业微信后台域名绑定的推广链接，才能获取访问用户的企微身份；未绑定的链接只能记录访问量，无法识别具体用户。
  • 数据有延迟：访问数据可能有几分钟延迟，实时性要求高的场景需注意。
  • 用户授权后才记录：用户首次访问时需同意网页授权，拒绝授权的用户无法被识别身份。

业务逻辑

查看访问用户是关联链路的价值闭环：整个域名关联链路的最终价值在于能够识别"哪些企微用户访问了推广内容"。只有完成总后台关联 → 企业微信绑定 → 客户端回显 → 取链接投放全流程后，才能在企微环境内完成网页授权并捕获用户身份，实现从推广到用户识别的数据闭环。
