## 1. 产品概述

### 1.1 产品定位

餐餐补是一套面向微信小程序用户的外卖优惠与现金补贴产品。用户通过小程序进入美团、饿了么、淘宝闪购等外卖会场完成下单，提交订单号并通过平台匹配后，可获得订单补贴；用户邀请好友参与，还可获得好友订单补贴和阶段性邀请奖励。

产品采用“一套小程序代码、多小程序账号、同一套后端”的 SaaS 形态。不同小程序通过请求头中的 `appid` 识别归属，并在会场配置、订单、邀请关系、收益流水、提现记录、微信身份和支付商户配置等环节进行逻辑隔离。

### 1.2 用户价值

- 用户可从外卖订单中获得现金补贴。
- 用户可邀请好友参与，并持续获得好友订单相关奖励。
- 补贴与奖励可直接发放到微信零钱。
- 用户可以查看自己的订单状态、到账记录、好友及奖励进度。

### 1.3 运营价值

- 统一配置多个外卖平台会场及跳转方式。
- 统一查看拉新用户、订单号、分享与奖励数据。
- 支持同一套系统承载现网小程序与客户小程序。
- 客户小程序可使用独立会场、推广位、邀请关系、收益钱包和支付商户。

### 1.4 本文范围

本文覆盖：

- 小程序 C 端页面与交互。
- 会场动态链接与外卖推广位。
- 订单号提交、匹配、结算和状态展示。
- 订单补贴、好友补贴、邀请奖励和提现。
- 邀请关系、分享记录和订阅通知。
- Admin 运营后台功能。
- 多小程序数据、支付与素材隔离。
- 关键数据对象、接口、任务队列和验收口径。

本文不展开 CRMEB 通用商城、普通电商订单、积分商城、会员体系、客服、企微等非餐餐补功能。

## 3. 产品架构与边界

### 3.1 系统组成

| 系统 | 项目 | 职责 |
|---|---|---|
| 微信小程序 | `saas_uniapp` | 用户登录、会场展示、订单提交、订单/好友/账单/提现页面 |
| Admin 运营后台 | `saas_admin` | 会场、素材、裂变规则、拉新用户、订单号和分享数据管理 |
| PHP API | `saas_crmeb` | 用户、订单、邀请关系、收益流水、提现、支付配置、后台接口 |
| Go API | `saas_crmeb/Go` | 首页会场列表、按小程序选择推广渠道、动态生成外卖跳转链接 |
| MySQL | 共用业务库 | 保存小程序、用户、订单、关系、流水、提现、链接和配置 |
| Redis/队列 | 共用基础设施 | 缓存、限流、异步订单匹配、结算与自动提现 |

### 3.2 核心链路

```text
用户打开小程序
  → 小程序自动携带当前 appid
  → Go API 返回该小程序可见的外卖会场及动态推广链接
  → 用户进入外卖平台下单
  → 用户提交订单号
  → PHP 创建待匹配记录并投递队列
  → 系统匹配联盟订单并完成结算
  → 生成订单补贴/好友补贴/邀请奖励流水
  → 订单补贴自动尝试打款，奖励金由用户手动提现
  → 按当前 appid 选择 OpenID、支付配置和微信商户号
```

### 3.3 多小程序原则

1. 小程序端请求必须携带当前账号的真实 `appid`。
2. 同一个自然人可以在多个小程序中对应同一个 `uid`，但业务数据按 `uid + appid` 隔离。
3. 当前小程序的微信身份使用该 `appid` 对应的 `openid`。
4. 资金打款使用该 `appid` 绑定的支付配置，禁止回退到其他小程序的商户号。
5. 未登记、已删除或无法识别的 appid 不得回退到全量现网数据。

### 4.3 首页会场

首页通过 Go 接口 `/goapi/cps/make_up_for_every_meal` 获取会场列表。每条会场可配置：

- 图标、业务名称、标题、副标题和排序。
- 平台类型：未知、饿了么、美团。
- 跳转类型：普通链接、外部小程序、当前小程序、不跳转、弹窗、各平台口令弹窗等。
- 跳转目标小程序 appid、原始 ID、活动 ID和路径/口令。
- 宿主小程序归属 `owner_appid`。

用户点击会场后，系统根据类型直接跳转或展示对应口令弹窗。对已绑定独立外卖推广位的客户小程序，Go 服务使用该小程序的 `takeout_channel_id` 动态生成链接和 SID；现网兼容范围使用默认渠道。

### 4.4 空数据与失败状态

- 会场接口成功但返回空数组：页面显示“重新加载”，不得持续无限加载。
- 会场接口请求失败：展示重新加载入口。
- 未登记或已删除 appid：接口返回空数组，不返回现网或客户专属会场。
- 用户未登录：触发小程序登录流程，完成后重新拉取用户相关数据。

## 5. 核心业务流程

### 5.1 登录与小程序识别

1. 小程序通过 `uni.getAccountInfoSync()` 获取当前小程序 appid。
2. `/api` 和 `/goapi` 请求统一携带：
   - `Form-type: routine`
   - `appid: 当前小程序 appid`
   - 登录后携带 `Authori-zation: Bearer <token>`
3. 后端根据 `eb_mini_program` 判断 appid 是否已登记、是否删除及所属 SaaS 客户。
4. 微信身份以 `uid + appid + user_type=routine` 查找对应 OpenID。

### 5.2 会场下单

1. 用户进入首页并获取当前小程序可见的会场。
2. Go 服务按小程序归属筛选 `eb_home_business`：
   - 客户小程序：只返回 `owner_appid=当前appid`。
   - 现网兼容小程序：返回空归属及当前 appid 专属数据。
   - 未知 appid：返回空数据。
3. 若小程序绑定了独立外卖渠道，则使用该渠道生成推广链接。
4. 用户跳转至外卖平台完成下单。
5. 用户返回餐餐补，复制并提交订单号。

### 5.3 提交订单号

接口：`POST /api/v2/takeout/upload_order`

已实现校验：

- 订单号不能为空，提交前删除中间空格。
- 同一订单号不能被不同用户重复使用。
- 已核销、处理中或已失效订单不可重复提交；“订单未支付”状态允许完成支付后重新提交。
- 用户同时只能有一笔未完成的处理中订单。
- 用户当天状态达到匹配阶段的订单最多 6 笔。
- 用户累计风控订单达到 7 笔后停止继续提交，并提示联系客服。

校验通过后：

1. 创建 `eb_take_out_order`，写入 `uid + 当前appid + 订单号`。
2. 初始状态为 `1（待匹配订单）`。
3. 延迟约 3 秒投递 `matchingTakeoutPullNew` 队列任务。

### 5.4 订单匹配与结算

订单由异步任务匹配联盟平台数据。支持的平台标识：

| platform | 平台 |
|---:|---|
| 0 | 未知 |
| 1 | 饿了么 |
| 2 | 美团 |
| 3 | 小票粉 |

后台原始状态：

| 状态 | 含义 |
|---:|---|
| 0 | 等待图片识别 |
| 1 | 待匹配订单 |
| 5 | 匹配双重订单中 |
| 10 | 已匹配完成，等待结算 |
| 15 | 已结算并完成正常分佣 |
| -100 | 订单状态已失效 |
| -101 | 未使用活动红包/未参加对应会场 |
| -102 | 订单号未匹配到 |
| -103 | 订单未支付 |
| -104 | 订单已退款 |
| -105 | 重复上传订单 |
| -106 | 小票订单超过限制或其他订单错误 |

小程序展示状态：

| 展示状态 | 判定 | 用户提示 |
|---|---|---|
| 识别中 | 原始状态为 0 | 截图正在识别中 |
| 匹配中 | 原始状态 0～14 | 预计到账或正在加急处理 |
| 待到账 | 状态 15 且对应流水未提现 | 低金额将与下一单合并 |
| 已到账 | 状态 15 且流水已提现 | 已提现到微信零钱 |
| 已失效 | 原始状态小于 0 | 根据未支付、退款、重复或未参加会场展示原因 |

### 5.5 收益入账

订单结算后写入 `eb_take_out_water`。收益类型为：

| type | 产品名称 | 收益归属 | 提现方式 |
|---:|---|---|---|
| 1 | 订单补贴 | 下单用户 | 结算后自动尝试提现 |
| 2 | 好友补贴 | 下单用户的邀请人 | 与邀请奖励合并后手动提现 |
| 3 | 邀请奖励 | 达成裂变阶段任务的邀请人 | 与好友补贴合并后手动提现 |

每条流水记录 `uid、appid、take_order_id、type、amount、is_withdraw、withdraw_id`。同一订单、用户和收益类型不得重复生成同类流水。

### 5.6 订单补贴自动到账

当 `type=1` 流水生成后：

1. 系统向默认业务队列投递 `saveTakeOUtWithdraw(uid, appid)`。
2. 仅聚合同一 `uid + appid` 下未提现的 `type=1` 流水。
3. 查找同一 `uid + appid` 的小程序 OpenID，不允许跨 appid 回退。
4. 聚合金额大于 0.30 元时创建 `type=1` 提现单。
5. 将关联流水暂时标记为已提现并关联提现单。
6. 按提现单 appid 查询该小程序支付配置并发起微信零钱打款。
7. 成功后提现单状态改为 `10（已到账）`，并发送到账通知。
8. 失败后提现单状态改为 `-1`，记录失败原因，并把关联流水恢复为未提现。

自动提现按 `uid + appid` 统计当天提现单数量，当前代码达到 10 次后不再自动创建新提现单。

### 5.7 好友补贴与邀请奖励提现

`type=2` 和 `type=3` 流水不会随订单立即自动打款。用户在“奖励金提现”页面主动申请：

1. 查询当前 `uid + appid` 的未提现且 `type<>1` 的流水。
2. 同一小程序当天已有成功的 `type=2` 提现单时，提示次日再来。
3. 使用 Redis 锁限制 60 秒内重复点击。
4. 按流水顺序累计金额，累计超过 39 元后停止继续加入本次提现。
5. 金额必须大于 0.30 元。
6. 使用当前 appid 的 OpenID 和支付商户配置发起打款。
7. 成功后记录到账并发送通知；失败时记录原因并恢复流水。

### 5.8 邀请关系

邀请分享路径包含 `spid=邀请人uid`，裂变分享还携带 `act_type=fission`。

邀请关系规则：

- 关系表唯一键为 `uid + appid`。
- 同一用户可在不同小程序绑定不同邀请人。
- 同一用户在同一小程序只能绑定一次，首次有效关系保留。
- 禁止自己邀请自己；邀请人必须存在。
- 客户小程序关系不得覆盖历史 `eb_user.take_out_super_uid`。
- `appid=''` 的关系用于现网历史兼容。

### 5.9 裂变任务

裂变任务根据邀请好友的首单完成情况生成奖励。后台支持：

- 活动开关与活动起止时间。
- 用户奖励上限。
- 前端展示的未完成任务数量。
- 基础奖励阶梯：达到指定人数获得指定激励金。
- 循环奖励：超过基础阶段后，每新增指定人数获得一笔激励金。
- 裂变规则富文本。

达到任务条件后生成 `type=3` 流水，并发送奖励到账类订阅通知。裂变活动配置当前为全局配置，不按 appid 独立存储。

### 5.10 分享与订阅通知

分享行为按 `uid + 日期 + appid` 记录：

- 分享次数。
- 注册人数。
- 当天注册并完成首单人数。
- 累计首单人数。

订阅通知包括补贴到账、活动进度、邀请成功和奖励到账等场景。订阅记录在查询时按当前 appid 过滤。

## 6. 小程序功能需求

### 6.1 首页

- 展示活动主视觉、地区、会场列表和常见问题。
- 支持不同跳转类型和平台口令弹窗。
- 支持订阅午餐/补贴提醒。
- 支持订单号提交入口及复制教程。
- 支持邀请链接进入后的弹窗引导。
- 新用户、老用户及裂变进入场景显示不同引导。
- 会场为空或接口失败时支持重新加载。

### 6.2 我的订单

- 分为全部、已到账、待到账、已失效四个页签。
- 展示订单号、平台、店铺、商品图、补贴金额、状态和时间。
- 匹配中的订单展示预计到账倒计时或加急提示。
- 未支付订单提示完成支付后重新上传。
- 无效订单支持返回首页重新参加活动。
- 列表支持分页加载。

### 6.3 全民补贴

- 展示活动规则、奖励阶梯和邀请进度。
- 展示可提现奖励金及累计到账金额。
- 展示好友列表及好友首单状态。
- 支持分享邀请和提醒好友参与。
- 支持进入奖励金提现页。

### 6.4 个人中心

- 展示头像、昵称和用户 ID。
- 展示已到账补贴、可提现余额、累计提现、邀请奖励和好友订单奖励。
- 提供我的订单、好友、账单、补贴规则和常见问题入口。
- 用户头像未完善时，部分账单、订单和提现入口先要求完善头像昵称。

### 6.5 账单

- 订单补贴：展示成功的 `type=1` 提现记录。
- 全民补贴：展示成功的 `type=2` 提现记录。
- 展示总补贴、订单补贴、全民补贴累计金额。

### 6.6 提现页

- 展示当前可提现奖励金。
- 当金额不足或当天已提现时按钮置为不可用样式。
- 点击后显示加载状态，防止用户重复操作。
- 成功后刷新余额并展示现金红包结果。
- 失败时展示后端返回的业务错误。
- 支持余额到账订阅提醒。

## 7. Admin 运营后台

### 7.1 菜单结构

现网菜单：

- 拉新列表
- 单号列表
- 裂变配置
- 链接配置
- 分享记录

客户菜单副本：

- 拉新列表-方笑天
- 单号列表-方笑天
- 裂变配置-方笑天
- 链接配置-方笑天
- 分享记录-方笑天

客户路由通过路由元信息 `tenant=customer、mpType=1` 标识。请求拦截器自动向查询参数和请求体注入 `mp_type=1`；数据隔离必须由服务端再次强制执行。

### 7.2 拉新列表

展示字段包括：

- 用户 ID、头像、昵称、注册时间。
- 推广好友数、首单好友数。
- 自身订单数、好友核销单数。
- 自身核销金额、好友返佣金额、总收益。
- 已提奖励金和奖励金余额。

支持：

- 查看用户的好友列表。
- 查看好友核销单数、返佣金额和绑定时间。
- 配置拉新规则富文本。
- 导出用户数据。

### 7.3 单号列表

支持按昵称、订单号、上级用户、状态、平台、风控状态和时间筛选，展示：

- 匹配单号、订单类型、店铺和商品信息。
- 支付金额、佣金、一级补贴、上级返佣。
- 用户及上级用户。
- 匹配、结算、封控、红包等状态。
- 上传时间、核销时间和失效原因。

支持导出订单数据，并可配置小票入口开关。

### 7.4 链接配置

支持新增、编辑和删除外卖拉新会场，配置：

- 排序、图标、业务名称、标题、副标题。
- 平台类型和跳转类型。
- 外部 appid、原始 ID、活动 ID、链接/口令和备注。
- 宿主小程序归属。

现网路由只能操作现网归属链接；客户路由只能操作客户归属链接。共享素材只允许引用，不允许客户路由删除。

### 7.5 图库

- 现网图库显示空归属素材。

### 7.6 裂变配置

- 活动状态和起止时间。
- 用户奖励上限。
- 裂变规则说明。
- 基础奖励阶梯。
- 单条循环奖励规则。

当前现状：现网和客户菜单虽然各有路由，但底层 `SystemConfig` 和 `TakeConfig` 仍为全局数据，两边修改会影响同一套裂变规则。

### 7.7 分享记录

按日期汇总：

- 分享人数、分享次数。
- 注册人数。
- 当天注册首单人数、累计首单人数。
- 当天激励金额。

支持进入日期详情查看每个用户的分享和转化数据。现网与客户路由按 appid 过滤。

## 8. 多小程序隔离规则

### 8.1 小程序归属来源

- 唯一可信来源：`eb_mini_program`。
- Admin 客户类型通过 `config/mp.php` 中的 `mp_type → supplier_id` 映射反查客户 appid。
- Go 服务通过 `eb_mini_program.supplier_id` 判定客户小程序。
- 当前测试代码的客户映射为 `mp_type=1 → supplier_id=1`；生产发布前需核对正式客户 ID。
- 不再使用 `CUSTOMER_SUPPLIER_IDS`、`CUSTOMER_MP_APPIDS` 作为归属来源。

### 8.2 隔离矩阵

| 数据对象 | 隔离字段 | 规则 |
|---|---|---|
| 会场链接 | `eb_home_business.owner_appid` | 客户严格匹配当前 appid；现网使用空归属兼容 |
| 图库素材 | `owner_appid + partner_visible` | 客户自产可写，平台共享只读 |
| 微信身份 | `eb_wechat_user.appid` | OpenID 必须与当前小程序一致 |
| 订单 | `eb_take_out_order.appid` | 提交、查询、匹配和结算均保留订单所属 appid |
| 收益流水 | `eb_take_out_water.appid` | 钱包按 `uid + appid` 计算 |
| 提现单 | `eb_take_out_user_withdraw.appid` | 打款按提现单 appid 选择支付商户 |
| 邀请关系 | `eb_take_out_user_relation.appid` | 同一用户可在不同小程序绑定不同上级 |
| 分享记录 | `eb_take_out_shares_record.appid` | 分享和转化按小程序统计 |
| 外卖渠道 | `eb_mini_program.takeout_channel_id` | 客户使用独立推广位，现网兼容默认渠道 |

### 8.3 现网兼容

- 历史空 `appid` 或空 `owner_appid` 数据归现网。
- 客户小程序禁止使用空归属数据兜底。
- 现网兼容小程序可见空归属及自身专属会场，但不得看到客户专属会场。
- 未知 appid 返回空数据，不放宽过滤条件。

### 8.4 支付隔离

1. 提现单必须保存 appid。
2. 通过 `eb_mini_program.payment_id` 查找对应支付配置。
3. 使用当前 appid 对应的 OpenID。
4. 客户支付配置缺失时提现失败，记录错误，不得使用现网商户号。
5. 支付失败时恢复关联流水，用户余额不得被无故扣除。

## 11. 非功能要求与运行依赖

### 11.1 安全

- 用户身份和 appid 必须由服务端校验，不允许只依赖前端传参决定数据权限。
- Admin 客户路由的 `mp_type` 必须在服务端转为固定客户 scope。
- 客户路由不得修改或删除现网数据和平台共享素材。
- 提现不得回退到其他小程序的 OpenID 或商户号。

### 11.2 幂等与一致性

- 同一订单号不能重复核销或被其他用户使用。
- 同一订单、用户和流水类型不能重复生成收益流水。
- 创建提现单和锁定流水必须在事务中完成。
- 打款失败必须恢复流水的可提现状态。
- 重复执行自动提现任务时，已被其他提现单锁定的流水不得再次打款。

### 11.3 性能与缓存

- Go 会场接口使用 Redis 缓存，缓存键包含 appid、openid 和 uid。
- 客户 appid 列表缓存约 60 秒。
- 裂变配置缓存约 600 秒。
- 会场动态链接接口超时时间为 3.5 秒，小程序需展示失败重试状态。

### 11.4 队列

- 默认业务队列名称应为 `CRMEB_PRO`。
- Swoole 必须存在 `CRMEB_PRO` 消费进程。
- `.env` 中 `[QUEUE] LISTEN_NAME` 不得为空；空值会覆盖代码默认值，使任务进入无人消费的空队列。
- 发布 PHP 队列逻辑后必须重启实际 Swoole/队列消费进程，仅执行 `queue:restart` 不等于启动不存在的进程。

### 11.5 日志与排障

支付、提现单创建、流水锁定、微信身份缺失和支付失败需要记录可定位日志。排查最小维度应包含：

- `uid`
- `appid`
- 外卖订单 ID/订单号
- 流水 ID
- 提现单 ID/提现单号
- 提现状态与失败原因
- 实际支付商户号

## 14. 已知差异与待确认项

### 14.1 提现最低金额边界不一致

- 页面文案写“单次最低 0.3 元”。
- 前端仅在金额 `<0.3` 时显示禁用，因此 0.30 元看起来可以点击。
- 后端自动提现和手动提现均要求金额 **大于** 0.30 元，恰好 0.30 元会被拒绝或继续等待合并。

待产品确认：最低门槛应为“达到 0.30 元”还是“超过 0.30 元”。确认后需统一前端文案、按钮条件和后端比较规则。

### 14.2 裂变配置当前未按小程序隔离

客户与现网均有独立菜单入口，但 `SystemConfig(config_tab_id=91)`、`eb_take_config` 和缓存键仍是全局的。任一入口修改后会影响所有小程序。

待产品确认：继续全局共用，还是为每个 appid 提供独立活动期、规则和奖励阶梯。

### 14.3 手动提现金额上限口径

页面文案写“最高 39～41 元”。代码按流水逐条累计，累计值首次超过 39 元后停止，因此最终金额取决于最后一条流水，不能保证固定落在 39～41 元。

待产品确认：是否允许按流水不可拆分导致的小幅超额，还是必须严格封顶 39 元。

### 14.4 自动提现次数与用户认知

自动订单补贴当前按 `uid + appid` 限制每天最多创建 10 笔提现单；用户手动奖励金提现每天最多成功 1 次。小程序页面主要展示“每天最多提现 1 次”，容易被理解为所有提现共用一次。

待产品确认并补充面向用户的分类说明。

### 14.5 全局展示数据

裂变页的滚动补贴数据 `subsidy_data` 当前从全局收益流水聚合并缓存，没有按 appid 隔离。数据经过昵称截断和头像替换，主要用于活动氛围展示。

待确认：该模块是否允许全平台共用，或要求客户小程序只展示自身数据。

### 14.6 当前测试环境队列配置异常

排查发现测试环境 `.env` 中：

```ini
[QUEUE]
LISTEN_NAME =
BATCH_LISTEN_NAME =
```

导致默认任务进入空名称队列，而 Swoole 消费 `CRMEB_PRO`，形成历史积压。该问题属于部署配置，不是产品逻辑；修复前不能批量消费历史积压任务，应先评估其中是否包含支付、通知和订单任务。

### 14.7 正式客户映射待发布确认

当前代码 `config/mp.php` 和 Go 常量以客户 ID `1` 识别方笑天，代码注释提示正式环境可能使用客户 ID `8`。发布前必须以实际 `eb_mini_program.supplier_id` 为准统一 PHP 与 Go 配置。
