## 0. 产品定义（本轮重构的核心）

**旧**：用户主动操纵猫咪做四个固定动作（挥手/碰杯/递菜/一起吃饭），结果固定、重复无聊。
**新**：**猫咪生活剧场**——用户不是来操纵猫咪，是来看猫咪之间发生了什么有趣故事；即使不操作，饭堂也一直在发生事情。

三条设计原则是递进关系，不是并列功能：

```
猫咪有性格（底层数据）→ 饭堂有故事（内容引擎）→ 用户间长弱关系（时间积累）
```

目标感觉：**温暖、轻松、热闹、治愈，有一点点荒诞和幽默。**
产品目标：每次打开都想问「今天饭堂里又发生什么有趣的事情了？」

## 1. 六条核心流程线（中间流程栏的 6 条线）

> 这是本次流程栏的主结构：左栏「流程」tab 下直接看到这 6 条线，每条线是一个完整可体验闭环。
> 每条线的步骤 `k` 指向帧 key，直接可点跳帧；带 `autoSheet` 的步骤会同时弹出对应弹层。

| # | 流程线 | 体验闭环 | 主要帧 / 弹层 |
|---|---|---|---|
| 01 | **猫咪偶遇** | 进饭堂 → 随机猫按性格开口 → 三选一（分它一口 / 假装没看见 / 聊两句）→ 不同反馈 | `encounter-stage` + `encounter-sheet` |
| 02 | **今日饭桌话题** | 看今日话题 → 选一个答案 → 看集体统计（如 68% 咖啡续命）→ 看其他猫的回答 | `topic-stage` + `topic-result` |
| 03 | **饭堂奇遇（盲盒）** | 开盲盒 → 随机完整小事件（超大碗面香飘饭堂…）→ 三选一 → 反馈，特殊事件入图鉴 | `chance-stage` + `chance-sheet` + `chance-gallery` |
| 04 | **饭搭子默契** | 看熟悉猫 → 相遇记录（初次→饭点熟人→固定→灵魂饭搭子）→ 解锁称号 | `buddy-stage` + `buddy-detail` |
| 05 | **饭堂传闻** | 饭堂动态流 → 读匿名传闻 → 传闻来自模拟行为数据 → 浏览下一条 | `rumor-stage` |
| 06 | **串门 · 看别家饭堂** | 打开饭堂列表 → 进别家饭堂（只读）→ 看猫和故事 → 回自己饭堂 | `hall-hop` |

**保留的既有流程**：落座状态机（入座询问 → 无订单 → 下单上菜 → 等饭中 → 收货 → 吃饭中）、印章墙、消费联动、猫咪资料。它们作为第 07/08/09 条线保留，不被六玩法覆盖。

## 2. 六种玩法与内容系统（批次 1 的落地清单）

### 2.1 猫咪性格体系（底层，贯穿所有玩法）
- 性格库 6 种：干饭王 / 社恐猫 / 戏精猫 / 打工猫 / 摆烂猫 / 美食家
- 每种性格有：典型口头禅、偶遇文案风格、随机事件反应、互动回复、饭堂动态表现
- 22 只猫保留现有「状态」（吃饭/咖啡/奶茶/发呆/休息），**叠加**一层性格标签（默认决策 ③：状态与性格并存，不互相替换）
- 性格影响：同一事件，不同性格猫的台词与表现不同

### 2.2 六类内容库（第一版预设文案 + 随机规则，不接 AI）
| 库 | 内容 | 关键要求 |
|---|---|---|
| 偶遇剧情库 | 每段含开场 + 台词 + 3 个选项 + 3 种反馈 | 同一猫可触发不同故事；按性格换文案 |
| 饭桌话题库 | 每日一题 + 4 个选项 + 集体统计 + 其他猫回答 | 参与后能看到统计与他人选择 |
| 随机事件库 | 完整小事件（有画面感文案 + 选项 + 反馈） | **不是随机换一句话**；特殊事件可入图鉴 |
| 饭堂传闻库 | 匿名播报文案，来自模拟行为数据 | 不暴露隐私，有社区感 |
| 饭搭子文案库 | 4 级关系文案 + 相遇次数描述 | 「这么巧，又遇见你了」 |
| 特殊事件图鉴 | 抽到过的稀有事件记录 | 可回看，给重复互动长期目标 |

### 2.3 防重复机制
- 已看过的内容记入 `state.seen`，优先抽没看过的
- 抽到过的进图鉴；同一事件不连续重复
- 互动/随机事件有频率限制（原型用「本轮已触发」提示模拟）

## 8. 返工 · 交互引擎改为「弹窗向导承接完整交互」（2026-11-19 第二轮）

**用户批评**："HTML 都没做，你知道什么是流程吗，用户的完整交互，哪个功能是把完整交互跑完的？落座也没跑完，太生硬了，要用弹窗去承接。"

**问题定性**：上一版把"流程"做成了页面跳转 + 卡片按钮 + toast，弹窗只是"结果展示"（做完了弹出来告知），不是"过程承接"（弹出来让你一步步操作）。这是根本性错误。

**对照参考稿（奶茶争霸赛）确认的正确做法**：每个流程步骤带 `data-go`（切帧）+ `data-autosheet`（同时弹窗），点步骤 = 切到对应页面状态 + 自动弹出承接该步交互的弹窗；弹窗里是真实可操作的选择/表单/按钮，一步步把流程走完。

**本次改造**：
- 新增**弹窗向导引擎** `state.wiz` + `wizardView()` + `startWiz()` / `applyWiz()` / `openAuto()`：弹窗内多步推进，每步带进度条（wzBar）。
- **落座改为完整 6 步弹窗链**：①要不要坐下 → ②选座位（可选/确认）→ ③点单吗 → ④上菜了 → ⑤等饭中→收货 → ⑥吃饭中·完成；旁观分支也能回到坐下；场景点空位同样进弹窗确认。每一步都在弹窗里推进，不再靠卡片按钮。
- **偶遇/奇遇/话题也改为弹窗链**：偶遇 3 步（搭话→三选一→反馈）、奇遇 3 步（未开封→事件三选一→反馈/入图鉴）、话题 2 步（四选一→统计）。
- 六玩法流程步骤点击自动接对应向导（`openAuto`），页面内按钮也统一走向导。
- 加健壮性防御：任何入口进向导都先保证数据就绪（避免 encounter/chance 为空崩溃）。

**验证**：JS 语法 OK；**弹窗链交互测试 18/18 全过**（落座 6 步 + 状态推进 + 旁观分支 + 偶遇/奇遇/话题各链）；9 条流程线 37 步骤、8 个带弹窗承接、无无效帧 key、10 个承接调用 OK；全 18 帧渲染 OK。

**进度条意义**：现在每个核心功能都有明确的"从头走到尾"的完整交互，且全部由弹窗承接——回应了用户"哪个功能把完整交互跑完"的质问。

## 10. 流程总览帧 + 流程编号前缀（2026-11-19 第四轮）

**改动**：
- **流程编号前缀**：左栏流程名显示改为 `001- 落座与用餐` … `010- 猫咪资料`（用 `String(f.id).padStart(3,'0')`，数据 id 保持 "01"–"10" 不动，零风险）。
