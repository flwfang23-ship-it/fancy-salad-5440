# AI 帖子免登录写入接口

前缀 `/api/public/evaluation`，不需要 Authorization、登录、Casbin 或素材库使用权限；没有列表/详情 GET 接口。原 `/api/platform` 接口保持不变。接口直接修改原业务数据，拿到地址的调用方均可增删改，请将此入口限制在实际需要的网络范围内。审计 created_by/updated_by 使用 0 表示匿名自动化。

页面实际对应：Classification=帖子分类、postContent=帖子、evaluation=发布人。

## 接口

| 方法 | 路径（相对前缀） | 请求 |
| --- | --- | --- |
| POST | /categories | `{"name":"美食"}` |
| PUT | /categories/:id | 同新增 |
| DELETE | /categories/:id | 无请求体 |
| POST | /publishers | `{"name":"作者","avatar_url":"https://example.com/avatar.png"}` |
| PUT | /publishers/:id | 同新增，全量提交名称和头像 |
| DELETE | /publishers/:id | 无请求体 |
| POST | /posts | 见下例 |
| PUT | /posts/:id | 同新增，全量替换；不是 PATCH |
| PUT | /posts/:id/status | `{"status":1}` 上架，2 下架 |
| DELETE | /posts/:id | 无请求体，先下架 |
| POST | /images | multipart/form-data，重复 `files` 字段上传 1～10 张 |

统一响应 `{"code":0,"message":"success","data":...}`，非零 code / 非 2xx 表示失败。新增分类、发布人和帖子返回带 id 的对象，请保存这些 id，用于后续修改/删除和建立关联，不需要查询接口。删除成功 data 为 null。

已有数据的 id 可从后台取得。类别已被帖子引用（包括已软删除的帖子）时不可删除；发布人有未删除的帖子时不可删除。

## 逐个接口：完整参数与请求体

下面列出全部 **11 个接口**。每个接口均免登录，不需要 Authorization 或 Cookie，也没有必填查询参数。

示例域名 `http://localhost:8080` 仅为占位，替换为后端实际地址；路径中的 12、34、56 分别是假设的分类、发布人、帖子 ID，必须换成实际 ID。JSON 请求使用 `Content-Type: application/json`。

成功响应外层统一如下，具体 data 内容见各接口说明；示例只展示核心字段：

```json
{"code":0,"message":"success","data":null}
```

失败时 HTTP 为非 2xx，code 非零，message 为失败原因，data 通常为 null。不要只检查是否收到了 HTTP 响应。

### 1. 新增帖子分类

`POST /api/public/evaluation/categories`

请求体参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 去除首尾空白后 1～50 字；分类名不能重复 |

请求体示例：

```json
{
  "name": "美食"
}
```

调用示例：

```sh
curl -X POST 'http://localhost:8080/api/public/evaluation/categories' \
  -H 'Content-Type: application/json' \
  --data-raw '{"name":"美食"}'
```

返回 data 为分类对象，包含 id、name、created_at 等字段。分类名重复会失败。

### 7. 新增帖子

`POST /api/public/evaluation/posts`

请求体参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| category_id | 正整数 | 是 | 有效的帖子分类 ID；不能为 null 或 0 |
| publisher_id | 非负整数 | 否 | 有效发布人 ID；省略或 0 时随机选择现有发布人；没有发布人时报错 |
| title | string | 是 | 去除首尾空白后 1～80 字 |
| content | string | 是 | 非空正文，支持 HTML；正文图片用 img 的 src 引用上传结果 URL |
| images | string[] | 条件必填 | 1～10 个图片地址，按顺序保存，第一张自动作为封面；每项非空且最长 500 字节 |
| cover_url | string | 条件必填 | 兼容单图：省略 images 时可用 cover_url；已传 images 时以 images[0] 为准。images=[] 不会回退到 cover_url |
| location | string | 否 | 最长 100 字；空字符串或省略默认广东 |
| status | integer | 否 | 1 上架，2 下架；省略默认 2 |
| initial_like_count | 非负整数 | 否 | 起始点赞；省略/null 则随机 400～900；传 0 保留 0 |
| initial_collect_count | 非负整数 | 否 | 起始收藏；省略/null 则随机 400～900；传 0 保留 0 |
| initial_share_count | 非负整数 | 否 | 起始转发；省略/null 则随机 400～900；传 0 保留 0 |

请求体示例：

```json
{
  "category_id": 12,
  "publisher_id": 34,
  "title": "这家店值得一试",
  "content": "<p>体验正文</p>",
  "images": [
    "https://example.com/01.jpg",
    "https://example.com/02.jpg"
  ],
  "location": "广州",
  "status": 2,
  "initial_like_count": 0,
  "initial_collect_count": 0,
  "initial_share_count": 0
}
```

调用示例：

```sh
curl -X POST 'http://localhost:8080/api/public/evaluation/posts' \
  -H 'Content-Type: application/json' \
  --data-raw '{"category_id":12,"publisher_id":34,"title":"这家店值得一试","content":"<p>体验正文</p>","images":["https://example.com/01.jpg","https://example.com/02.jpg"],"location":"广州","status":2,"initial_like_count":0,"initial_collect_count":0,"initial_share_count":0}'
```

返回 data 为帖子对象，包含 id、category_id、publisher_id、title、content、cover_url、images、status、location、初始/实际互动计数等字段。保存 data.id 供后续操作。

### 11. 批量上传图片（含单张上传）

`POST /api/public/evaluation/images`

没有路径参数、查询参数。请求体为 **multipart/form-data，不是 JSON**；不要手动设置 Content-Type 的 boundary，由 curl/HTTP 客户端自动生成。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| files | file，可重复 | 是 | 同名字段传 1～10 个本地图片文件；单张上传也使用 files 字段，不是 file |
| module | string | 否 | post-cover（默认，帖子图集）、post-content（正文图片）、publisher-avatar（发布人头像） |

请求体结构示例（表示 multipart 表单字段，不是 JSON）：

```text
module: post-cover
files: <01.jpg 的二进制内容>
files: <02.png 的二进制内容>
```

多图调用示例：

```sh
curl -X POST 'http://localhost:8080/api/public/evaluation/images' \
  -F 'module=post-cover' \
  -F 'files=@/absolute/path/01.jpg' \
  -F 'files=@/absolute/path/02.png'
```

单张头像调用示例：

```sh
curl -X POST 'http://localhost:8080/api/public/evaluation/images' \
  -F 'module=publisher-avatar' \
  -F 'files=@/absolute/path/avatar.png'
```

返回 data 为数组，每项包含 index（从 0 开始）、name（原文件名），成功项有 upload 对象，失败项有 error。upload 内含 url、file_key、file_name、file_size、file_ext、id（匿名上传不写附件表，id 为 0）。业务请求取 upload.url，不能把本地文件路径或整个 upload 对象填入 images/avatar_url。

支持 jpg/jpeg/png/gif/webp；单张上限为 upload.max_size 与 10MB 中较小的有效值；请求体硬上限 101MB。参数、类型或大小校验失败会整批拒绝；写存储阶段可能部分成功，必须逐项检查。详细返回示例与重试规则见下文。

## 图片：先上传，再提交业务数据

AI 不能将本机路径直接当作服务端图片地址。让运行 AI 的程序读取本地图片，通过 multipart 上传；远程图片若要转存，先由调用程序下载再上传，服务端不代抓远程 URL。

```sh
BASE='http://localhost:8080'
curl -X POST "$BASE/api/public/evaluation/images" \
  -F 'module=post-cover' \
  -F 'files=@/absolute/path/01.jpg' \
  -F 'files=@/absolute/path/02.png'
```

可选 module：post-cover（默认，帖子图片）、post-content（正文图片）、publisher-avatar（头像）。支持 jpg/jpeg/png/gif/webp；单张不超过配置 upload.max_size，且硬上限 10MB；单次请求上限 101MB。全部文件先校验，再写存储。图片按上传顺序返回：

```json
{"code":0,"message":"success","data":[
  {"index":0,"name":"01.jpg","upload":{"url":"https://your-domain/api/files/post-cover/.../a.jpg","file_key":"post-cover/.../a.jpg"}},
  {"index":1,"name":"02.png","error":"图片存储失败，请单独重试该文件"}
]}
```

每项成功有 upload，失败有 error。即便 HTTP 200 / code=0，也须逐项检查；成功项保留，失败项单独重传，收齐后按 index 排序再创建帖子。上传文件与业务保存不在同一事务，保存失败不会自动删除已上传文件。删除帖子也不会删除图片。

头像使用成功结果的 upload.url 填 avatar_url（支持 HTTP(S) 地址和 / 开头的站内路径）。匿名接口允许直接 URL 头像；原后台新增头像仍须素材库。已有素材也可提交 `{"name":"作者","avatar_source":"library","avatar_value":"素材object_key"}`，仍校验素材存在且可用，但不校验角色权限。不要把带过期签名的素材预览链接当成持久头像。

正文图片先用 post-content 上传，将返回 URL 放入 HTML 的 img src 中；帖子图集将 URL 依次放入 images，第一张自动成为封面。超过 10 张图片应拆到不同帖子；可分批上传，单篇仍最多 10 张。

## 建帖示例

先创建分类和发布人，从响应 data.id 取得 category_id 和 publisher_id：

```json
{
  "category_id": 12,
  "publisher_id": 34,
  "title": "这家店值得一试",
  "content": "<p>体验正文</p><p><img src=\"https://example.com/body.jpg\" /></p>",
  "images": ["https://example.com/01.jpg", "https://example.com/02.jpg"],
  "location": "广州",
  "status": 2,
  "initial_like_count": 0,
  "initial_collect_count": 0,
  "initial_share_count": 0
}
```

标题 1～80 字，正文和有效 category_id 必填；publisher_id 留空/0 时随机选一个现有发布人。status 默认 2（下架），可传 1 上架。location 留空默认广东。三个初始互动数留空各随机 400～900，明确传 0 则保留 0。兼容只传 cover_url 作为单图，推荐统一传 images。

PUT 是全量替换；省略图片/分类会校验失败，省略发布人/互动数会重新随机，省略 status 会按默认 2 保存。调用程序应保存完整原始请求用于后续修改。

## AI 批量操作顺序

1. 新建分类和发布人并保存返回 id；已知 id 可直接复用。
2. 每篇上传图片、逐项校验结果，再提交 POST /posts，并保存帖子 id、完整请求和图片 URL。
3. 批量修改/删除时，对已保存 id 循环调用 PUT/DELETE。写入接口为单条操作，图片接口支持批量。
4. 删除顺序：下架帖子 → 删除帖子 → 删除无帖子的发布人；已被帖子引用的分类仍受引用限制。

接口没有幂等键，POST 超时后不要盲目重复提交，以免重复建帖；调用方应记录成功响应，无法确认结果时先在原后台核实。本变更无需数据库迁移。
