# 公开订阅推送统计查询接口

本接口查询消息成功发送数量和点击人数，不触发实际消息推送。查询获取的订阅人数和订阅次数请使用[订阅获取统计接口](公开订阅获取统计接口.md)。

## 请求

正式环境基础地址：`https://rapid.ycyygl.top`

完整接口：`GET https://rapid.ycyygl.top/api/v1/public/subscription-push-reports`

请求方式：`GET`；参数位置：URL Query；请求体：无。无需设置 `Content-Type`，可选请求头为 `Accept: application/json`。

无需登录，不需要 `Authorization`、Token 或 Cookie。每行是一个“发送日期 + 小程序”的汇总，复用后台推送统计口径，不返回用户、OpenID、具体消息任务或模板明细。

所有参数通过 URL Query 传入：

| 参数 | 类型 | 必填 | 默认值 / 说明 |
| --- | --- | --- | --- |
| `start_date` | string | 是 | 开始日期，严格 `YYYY-MM-DD`，包含当日 |
| `end_date` | string | 是 | 结束日期，严格 `YYYY-MM-DD`，包含当日 |
| `app_id` | string | 否 | 省略或为空查询全部小程序；最长 64 字符，仅允许英文字母、数字、下划线、连字符，例如 `wx3a5e32bc6f55c574` |
| `send_mode` | string | 否 | 省略或为空查询全部；`scheduled` 定时发送、`instant` 即时发送；不能传 `all` |
| `page` | integer | 否 | 默认 1，范围 1～1000000；显式传 0 不合法 |
| `page_size` | integer | 否 | 默认 20，范围 1～100 |
| `scope` | string | 否 | 默认汇总，建议省略；仅允许 `summary` 或空；`templates` 返回 400 |

日期按北京时间解释，开始日期不得晚于结束日期，结束日期不得晚于今天；单次最多查询连续 366 个自然日，最早年份 1000。与公开订阅获取日报不同，本接口可以查询今天尚在变化的发送数据。


按小程序和发送方式筛选时，追加 `app_id=wx1234567890abcdef`、`send_mode=scheduled`。查询全部时省略对应参数，不要传 `send_mode=all`。

## 正式环境完整调用方案

### 1. 最小请求（只传两个必填参数）

```bash
curl --show-error --get 'https://rapid.ycyygl.top/api/v1/public/subscription-push-reports' \
  --data-urlencode 'start_date=2026-11-10' \
  --data-urlencode 'end_date=2026-11-10'
```

可直接访问：[https://rapid.ycyygl.top/api/v1/public/subscription-push-reports?start_date=2026-11-10&end_date=2026-11-10](https://rapid.ycyygl.top/api/v1/public/subscription-push-reports?start_date=2026-11-10&end_date=2026-11-10)。省略 `app_id` 时查询全部小程序，省略分页参数时使用 `page=1&page_size=20`。

### 2. 按小程序筛选并指定分页

```bash
curl --show-error --get 'https://rapid.ycyygl.top/api/v1/public/subscription-push-reports' \
  --header 'Accept: application/json' \
  --data-urlencode 'start_date=2026-11-01' \
  --data-urlencode 'end_date=2026-11-10' \
  --data-urlencode 'app_id=wx3a5e32bc6f55c574' \
  --data-urlencode 'send_mode=scheduled' \
  --data-urlencode 'page=1' \
  --data-urlencode 'page_size=100'
```

示例日期为固定历史日期，可替换为业务所需日期；示例 AppID 为线上验证使用的小程序，可替换为目标小程序 AppID。

### 3. JavaScript / Node.js 调用

以下示例适用于支持 `fetch` 的 Node.js 18+ 环境。浏览器跨域调用还需满足部署环境的 CORS 配置；本次线上验证使用服务端请求。

```javascript
async function getSubscriptionPushReports({
  start_date,
  end_date,
  app_id,
  send_mode,
  page = 1,
  page_size = 20,
}) {
  if (!start_date || !end_date) {
    throw new Error("start_date 和 end_date 必传");
  }
  const url = new URL("https://rapid.ycyygl.top/api/v1/public/subscription-push-reports");
  const params = { start_date, end_date, app_id, send_mode, page, page_size };
  for (const [key, value] of Object.entries(params)) {
    if (value !== undefined && value !== null && value !== "") {
      url.searchParams.set(key, String(value));
    }
  }
  const response = await fetch(url, {
    method: "GET",
    headers: { Accept: "application/json" },
    credentials: "omit",
    signal: AbortSignal.timeout(15000),
  });
  // 非 JSON 的网关错误或网络/超时错误也会抛出，由调用方统一处理。
  const body = await response.json();
  if (!response.ok || body.code !== 0) {
    throw new Error(`HTTP ${response.status}, code=${body.code}: ${body.msg}`);
  }
  return body.data;
}

try {
  const data = await getSubscriptionPushReports({
    start_date: "2026-11-01",
    end_date: "2026-11-10",
    app_id: "wx3a5e32bc6f55c574", // 可选：省略查询全部小程序
    send_mode: "scheduled", // 可选：省略查询全部发送方式
    page: 1,
    page_size: 100,
  });
  console.log(data.items);
  console.log("符合条件的总条数：", String(data.total));
} catch (error) {
  console.error("查询失败：", error.message);
}
```

### 4. 分页及结果处理

- 查询下一页时保留日期、AppID 和其他筛选条件，仅递增 `page`。
- `total` 是汇总记录条数；需要读取全部数据时，持续翻页，直到 `items` 为空，或 `BigInt(page) * BigInt(page_size) >= BigInt(total)`。页码不能超过参数表规定的最大值，大范围查询可按日期拆分。
- `items: []` 是正常成功响应，不应作为请求失败；不要把未返回的日期直接解释为零。
- 统计值及 `total` 兼容 `number | string`；展示用 `String(value)`，精确整数运算用 `BigInt(value)`。
- 参数错误（HTTP 400）应修改参数再请求；服务不可用或超时（503、504）可有限重试。调用时不传登录信息，也不需要传内部服务身份头。

## 返回数据

HTTP 200，使用统一的 `code/data/msg` 格式。示例数值仅用于说明结构：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "items": [
      {
        "report_date": "2026-11-08",
        "app_id": "wx1234567890abcdef",
        "send_count": 100,
        "tracked_send_count": 100,
        "click_count": 12,
        "scheduled_count": 80,
        "instant_count": 20,
        "manual_count": 5,
        "send_times": "11:00、18:30",
        "template_count": 3,
        "batch_count": 2,
        "raw_click_count": 15,
        "template_code": "",
        "template_name": "",
        "send_mode": ""
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 100
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `data.items` | 当前页汇总，按发送日期倒序、小程序 AppID 升序排列 |
| `data.total` | 符合条件的“日期 + 小程序”汇总行数，不是发送总量或总页数 |
| `data.page` / `data.page_size` | 实际页码及每页条数 |
| `report_date` | 消息发送成功日期，北京时间 |
| `app_id` | 小程序 AppID；接口不包含小程序名称 |
| `send_count` | 微信明确返回成功的消息数量，不是订阅授权次数、待发数量或发送尝试次数 |
| `tracked_send_count` | 携带点击任务参数、支持点击采集的成功发送数量 |
| `click_count` | 已采集到的点击人数，在同一发送日期和小程序内跨消息、跨模板按用户去重 |
| `scheduled_count` / `instant_count` | 当前筛选条件下，定时/即时发送成功的消息数量 |
| `manual_count` | 手动触发发送成功的消息数量，已包含在 `instant_count` 中，不可额外累加 |
| `send_times` | 定时发送时刻，多个时刻用 `、` 分隔；仅有即时发送时为空 |
| `template_count` | 成功发送覆盖的业务模板种类数 |
| `batch_count` | 定时发送的“模板 + 发送时刻”组合数量 |
| `raw_click_count` | 已采集点击次数，未按用户去重，仅供参考 |
| `template_code` / `template_name` / `send_mode` | 复用管理员响应结构；汇总查询中为空，不表示筛选条件失效 |

计数和 `total` 使用项目通用整数序列化：JavaScript 安全整数范围内返回 JSON 数字，超过范围返回十进制字符串。调用方应兼容 `number | string`，大整数运算使用 `BigInt`。`page` 和 `page_size` 始终是数字。

没有记录或超出末页时返回 `items: []`，不会为无发送记录的日期补零。

## 点击率与更新口径

接口不直接返回格式化点击率。`send_count > 0` 且 `tracked_send_count == send_count` 时，可计算：

```text
点击率 = click_count / send_count × 100%
```

示例是 12%。如果 `tracked_send_count < send_count`，说明存在未采集点击的旧消息；此时 `click_count` 只是已记录的部分，点击人数和点击率建议显示“—”，不能把历史未采集当作零点击。

成功发送按任务的发送成功时间统计，只计微信明确成功的记录。跨日点击仍归到原消息发送日期，所以过去日期的点击人数也可能继续变化。接口实时读取现有发送任务和点击统计，不依赖午夜日报任务、不触发推送，也不创建统计任务。

## 错误响应

```json
{"code": 40001, "data": null, "msg": "invalid query parameters"}
```

| HTTP 状态 | code | 含义 |
| --- | --- | --- |
| 400 | 40001 | 参数缺失、日期无效、范围超限、AppID 格式错误、分页越界或请求模板明细 |
| 500 | 50001 | 内部查询失败 |
| 503 | 50301 | points 服务不可用或未升级 |
| 504 | 50401 | 下游查询超时 |

客户端应同时检查 HTTP 状态和业务 `code`，不要匹配 `msg` 文本。400 应修正参数；503、504 可稍后有限重试，避免无限重试。
