# 公开订阅获取统计（日报）查询接口

本接口统计每天获取的订阅人数和订阅次数，“日报”指按天汇总的订阅获取统计。查询推送成功量和点击人数请使用[订阅推送统计接口](公开订阅推送统计接口.md)。

## 请求

正式环境基础地址：`https://rapid.ycyygl.top`

完整接口：`GET https://rapid.ycyygl.top/api/v1/public/subscription-daily-reports`

请求方式：`GET`；参数位置：URL Query；请求体：无。无需设置 `Content-Type`，可选请求头为 `Accept: application/json`。

无需登录，无需 `Authorization`、Token 或 Cookie。公开查询已汇总日报，可按小程序筛选；每行代表一个日期和一个小程序，不返回模板明细。

所有参数通过 URL Query 传入：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `start_date` | string | 是 | 开始日期，严格 `YYYY-MM-DD`，包含当日 |
| `end_date` | string | 是 | 结束日期，严格 `YYYY-MM-DD`，包含当日 |
| `app_id` | string | 否 | 小程序 AppID，不传或传空字符串时查询全部小程序，例如 `wx1234567890abcdef`，最长 64 字符；仅允许英文字母、数字、下划线、连字符 |
| `page` | integer | 否 | 页码，从 1 开始，默认 1，最大 2147483647；显式传 0 不合法 |
| `page_size` | integer | 否 | 每页条数，默认 20，范围 1～100 |

日期按北京时间（Asia/Shanghai，UTC+8）解释。起止日期必须早于今天，开始日期不得晚于结束日期。单次最多查询连续 366 个自然日，最早支持年份为 1000。支持起止日期相同，查询单日报表。必填参数为空、无效日期、超出范围或反向时间区间返回 400。


查询全部小程序时，省略上述 `app_id` 参数即可。仍按“日期 + 小程序”逐行返回，`total` 是所有符合条件的小程序日报条数，不会把不同小程序合并为一条。

只支持上述查询参数，不支持通过 `scope` 切换模板明细。

## 正式环境完整调用方案

### 1. 最小请求（只传两个必填参数）

```bash
curl --show-error --get 'https://rapid.ycyygl.top/api/v1/public/subscription-daily-reports' \
  --data-urlencode 'start_date=2026-11-10' \
  --data-urlencode 'end_date=2026-11-10'
```

可直接访问：[https://rapid.ycyygl.top/api/v1/public/subscription-daily-reports?start_date=2026-11-10&end_date=2026-11-10](https://rapid.ycyygl.top/api/v1/public/subscription-daily-reports?start_date=2026-11-10&end_date=2026-11-10)。省略 `app_id` 时查询全部小程序，省略分页参数时使用 `page=1&page_size=20`。

### 2. 按小程序筛选并指定分页

```bash
curl --show-error --get 'https://rapid.ycyygl.top/api/v1/public/subscription-daily-reports' \
  --header 'Accept: application/json' \
  --data-urlencode 'start_date=2026-11-01' \
  --data-urlencode 'end_date=2026-11-10' \
  --data-urlencode 'app_id=wx3a5e32bc6f55c574' \
  --data-urlencode 'page=1' \
  --data-urlencode 'page_size=100'
```

示例日期为固定历史日期，可替换为业务所需日期；示例 AppID 为线上验证使用的小程序，可替换为目标小程序 AppID。

### 3. JavaScript / Node.js 调用

以下示例适用于支持 `fetch` 的 Node.js 18+ 环境。浏览器跨域调用还需满足部署环境的 CORS 配置；本次线上验证使用服务端请求。

```javascript
async function getSubscriptionDailyReports({
  start_date,
  end_date,
  app_id,
  page = 1,
  page_size = 20,
}) {
  if (!start_date || !end_date) {
    throw new Error("start_date 和 end_date 必传");
  }
  const url = new URL("https://rapid.ycyygl.top/api/v1/public/subscription-daily-reports");
  const params = { start_date, end_date, app_id, page, page_size };
  for (const [key, value] of Object.entries(params)) {
    if (value !== undefined && value !== null && value !== "") {
      url.searchParams.set(key, String(value));
    }
  }
  const response = await fetch(url, {
    method: "GET",
    headers: { Accept: "application/json" },
    credentials: "omit",
    signal: AbortSignal.timeout(15000),
  });
  // 非 JSON 的网关错误或网络/超时错误也会抛出，由调用方统一处理。
  const body = await response.json();
  if (!response.ok || body.code !== 0) {
    throw new Error(`HTTP ${response.status}, code=${body.code}: ${body.msg}`);
  }
  return body.data;
}

try {
  const data = await getSubscriptionDailyReports({
    start_date: "2026-11-01",
    end_date: "2026-11-10",
    app_id: "wx3a5e32bc6f55c574", // 可选：省略查询全部小程序
    page: 1,
    page_size: 100,
  });
  console.log(data.items);
  console.log("符合条件的总条数：", String(data.total));
} catch (error) {
  console.error("查询失败：", error.message);
}
```

### 4. 分页及结果处理

- 查询下一页时保留日期、AppID 和其他筛选条件，仅递增 `page`。
- `total` 是汇总记录条数；需要读取全部数据时，持续翻页，直到 `items` 为空，或 `BigInt(page) * BigInt(page_size) >= BigInt(total)`。页码不能超过参数表规定的最大值，大范围查询可按日期拆分。
- `items: []` 是正常成功响应，不应作为请求失败；不要把未返回的日期直接解释为零。
- 统计值及 `total` 兼容 `number | string`；展示用 `String(value)`，精确整数运算用 `BigInt(value)`。
- 参数错误（HTTP 400）应修改参数再请求；服务不可用或超时（503、504）可有限重试。调用时不传登录信息，也不需要传内部服务身份头。

## 成功响应

HTTP 200，使用项目统一的 `code/data/msg` 格式。以下数值仅为示例：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "items": [
      {
        "report_date": "2026-11-04",
        "app_id": "wx1234567890abcdef",
        "app_name": "积分小程序",
        "active": { "total": 524, "new_users": 206, "old_users": 318 },
        "subscribers": { "total": 300, "new_users": 100, "old_users": 200 },
        "subscriptions": { "total": 420, "new_users": 130, "old_users": 290 },
        "subscriber_totals_available": true
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number | 0 表示请求成功 |
| `msg` | string | 响应说明 |
| `data.items` | array | 当前页日报，按统计日期倒序排列 |
| `data.total` | number 或 string | 满足条件的报表总条数，不是人数或总页数 |
| `data.page` | number | 当前页码 |
| `data.page_size` | number | 当前每页条数 |
| `items[].report_date` | string | 北京时间统计日期 |
| `items[].app_id` | string | 小程序 AppID |
| `items[].app_name` | string | 汇总时的小程序名称快照；配置已移除且无法查询名称时可能为 AppID |
| `items[].active` | object | 全平台日活及其中新老用户人数，沿用当前后台全平台统计口径 |
| `items[].subscribers` | object | 该小程序当日跨模板去重的订阅人数及新老用户人数 |
| `items[].subscriptions` | object | 该小程序当日所有模板的订阅次数及新老用户次数 |
| `items[].subscriber_totals_available` | boolean | 跨模板去重订阅人数是否可用，历史未重算报表可能为 false |

三个统计对象都包含 `total`（总数）、`new_users`（新用户对应数值）、`old_users`（老用户对应数值）。所有计数（`total`、`new_users`、`old_users`）及 `data.total` 使用项目通用整数序列化：JavaScript 安全整数范围内返回 JSON 数字，超过范围返回十进制字符串。调用方应兼容 `number | string`；展示时可用 `String(value)`，需要精确整数运算时可用 `BigInt(value)`，不要将大整数字符串直接转为 `Number`。`page` 和 `page_size` 始终返回数字。

无记录、AppID 未匹配或请求页码超过末页时，仍返回 HTTP 200：`items: []`；`total` 保持符合条件的实际条数。不会为缺失日期补零；上线前没有生成日报的日期可以没有记录，缺失记录不等于订阅量为零。

## 统计口径与更新

- 北京时间每日 00:00 汇总前一天，接口读取已生成的报表，不触发实时统计或任务执行。
- **日活是全平台口径，不是指定小程序的独立日活。** 不同小程序行的日活会重复，不能累加。
- 用户注册当天为新用户，其后为老用户，按北京时间日期划分。
- 订阅人数在该小程序内跨模板去重，同一个用户订阅多个模板只计一人；同一用户在不同日期出现，不能简单累加得到区间去重人数。
- 订阅次数为各模板次数之和。只计成功上报的允许订阅事件；相同请求 ID 的补报不会重复计数，不代表消息实际发送成功次数。
- `subscriber_totals_available=false` 表示该历史日期尚未计算跨模板去重人数。此时 `subscribers` 内的 0 为占位值，**应展示“—”或“待重算”，不能解释为真实零人数**；日活、订阅次数仍可读取。重算对应日期后可用。
- 旧的跨小程序汇总记录没有 AppID，不传 `app_id` 时仍会返回此类历史汇总；其 `app_id`、`app_name` 为空，可显示“历史汇总（未区分小程序）”。传入具体 `app_id` 时不会匹配这些记录，需要重算对应日期才能按小程序查询。
- 数据受任务完成时间影响，午夜触发后可能尚未生成昨日报表；服务重算同一日期后，查询结果可能更新。

## 错误响应

```json
{
  "code": 40001,
  "data": null,
  "msg": "invalid query parameters"
}
```

`msg` 用于展示，客户端应按 HTTP 状态和 `code` 判断错误类型，不要匹配消息文本。

| HTTP 状态 | code | 含义 |
| --- | --- | --- |
| 400 | 40001 | 参数缺失、分页越界、小程序 ID 格式错误或日期范围不合法 |
| 500 | 50001 | 内部查询失败 |
| 503 | 50301 | task 服务不可用或尚未就绪 |
| 504 | 50401 | 下游查询超时 |

此接口开放匿名只读查询。创建、重跑任务及管理员查询接口仍要求管理员登录。服务间 RPC 仍只允许网关身份调用公开查询方法，无需客户端提供该身份。

## 发布

先升级 `task` 服务，再升级 `gateway` 服务。该接口复用现有日报表，不新增数据库迁移；此前报表所需的历史迁移仍须正常执行。
